AI 转换任务的运行与停止：把「整批」的停止从一条 AI 调用里搬出来

现在的停止入口错位：AI 会话树里的一行是 一次 AI 调用（整批任务里的一小笔）， 而它详情里的「停止」停的却是 整条转换流。想停这一笔的人误杀整批，想停整批的人找不到入口。 本稿把停止收归流级：面板顶部常驻「转换运行中」横幅，页内转换条与它同口径； 记录详情不再提供停止，只说明归属。

  • 绿 = 完成 / 答对
  • 陶土橙 = 进行中 / 当前 / 待抉择
  • 红 = 失败 / 答错
  • 弱灰 = 排队 / 取消
01

对比屏 · 现状两处表面

按 reference/current-state.md 忠实复现 · 标注粒度错位点

两处表面各有一套「停止」，口径都是整条转换流，但所处的视觉位置暗示的粒度完全不同： 页内转换条在任务顶上（读起来像整批），记录详情在一条小记录里（读起来像这一笔）。

粒度错位点

  • 1记录级停止钮的语义越界。树里一行 = 一次 AI 调用（第 12 批 · 8 题），点它详情里的「停止」，实际执行的是「当前篇 stopped + 剩余篇全部 cancelled + 汇总通知」。界面给的是小粒度，动作是大粒度 —— 想停这一笔的人误杀整批。
  • 2页内停止钮没有范围说明。文案只有「停止」二字，与「复制」同体量并排，既不突出也无范围；用户无法从按钮本身读出它停的是整批。
  • 3抉择态的两个钮没有倾向。「保留已生成」与「全部丢弃」同体量并列，安全项与破坏项看起来一样重，且不交代停在哪一篇、哪些被取消。
  • 4面板缺流级呈现，队列全景也只活在页内文字里。批量队列运行时面板里只有「转换 · 文档A」组（running）与历史组（done），没有一行说明「整批队列正在跑」；分篇六态（排队 / 进行 / 完成 / 跳过 / 停止 / 失败）随状态行滚动更新，滚过即消失，两个表面互不可见 —— 想停整批的人不会想到面板，更不会想到要进某条小记录的详情。
02

重设计屏 · 三个状态

批量队列运行中 / 单篇运行中 / 停止后抉择态

同一个原则贯穿三个状态：停止只有一个粒度 —— 整条转换流，且只在流级入口出现。 页内转换条与面板横幅是同一个动作的两个位置，文案、颜色、确认方式完全一致； 记录详情不再出现停止，改为一行归属说明指向流级入口。

03

四个问题的本稿采用

每问一句结论 · 一行为理由
Q1

流级停止入口住哪？

本稿采用 面板顶部给一条常驻「转换运行中」流级横幅（队列名 + 按篇着色构成条 + 第 i/N 篇 + 累计题数 + 「停止整批转换」），与页内转换条同口径并列，两者文案与二次确认完全一致。

理由：停止是流级动作，入口必须与流同层且常驻可见；横幅放在树的上方，让「整批」先于「某笔」被看到，用户不需要先猜到要进哪条记录。

Q2

记录级「停止」钮去留？

本稿采用 去掉。记录详情底部不再有停止按钮，原位换一行归属说明：「本记录是队列中的第 12 批，单笔 AI 调用不可单独中止」，并把停止指引回顶部横幅。

理由：一条记录 = 一次 AI 调用，本来就不存在「单独停这一笔」的能力，保留按钮只能靠改文案补救；而改标注仍会把「这里能停」的错觉留在用户视线最强的位置，且与横幅形成两个同功能入口。去掉后粒度与语义唯一对应。

Q3

批量队列全景进不进面板？

本稿采用 进，用两层密度：横幅常驻一行六态计数徽标（完成 / 跳过 / 进行中 / 失败 / 取消 / 排队，零值压暗）， 加上一条按篇着色的队列构成条；点「收起分篇」展开为逐篇行列表（序号 / 篇名 / 状态 / 本篇注记 / 本篇进度），当前篇高亮。

理由：只给计数徽标会让「哪一篇出了问题、停在哪一篇」无从查证；纯状态点阵列又无法承载篇名与原因。摘要常驻 + 全量按需展开，既不挤占面板，又能一眼看出队列构成。

Q4

运行中进度的层级分配？

本稿采用 页内转换条给全量（队列构成条 + 第 i/N 篇 + 本篇已读 % + 累计题数 + 已生成批数，单篇时自动收敛为一条已读进度）； 面板横幅给摘要（同一条队列构成条 + 第 i/N + 本篇已读 % + 累计题数，展开后可得全量分篇）； 记录详情只给本笔局部量（本轮次题数、批号、耗时），不出现全局进度。

理由：两个表面共享同一组数字，避免出现两套进度互相矛盾；记录是执行明细，重复全局进度只会稀释它自己的信息。
