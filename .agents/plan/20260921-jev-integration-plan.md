## 〇、先说人话：Jev 是什么、凭什么适合这个插件

咱们插件现在用的 AI（转换出题、学伴台词、统计建议）是「作文型」的：喂一大段
材料，它回一大段文字，代码还得自己解析、还得防它格式跑偏。

Jev 是另一种：**只做判断题的模型**。给它材料 + 一组问题，它只回结构化答案——

- **是/否**（noul）：`{答案: 是, 概率: 0.93}` ——概率就是它觉得「是」的把握；
- **单选**（choice）：从你给的选项里挑一个，附每个选项的概率和总体置信度；
- **打分**（score）：按你定义的 1~5 档打分，每档有具体情形描述。

它不写文章、不解释、不跑题。好处三个：**快、便宜、格式永远不坏**。而且置信度
是显式的——把握不足时代码能选择「不当家，交给人」。

一个具体例子：转换出的题目「下列哪项是等差数列…」+ 原文段落，问 Jev
「这道题的答案能否从材料唯一推出？」它回 `{是, 0.91}`——烂题在落库前就被点名，
而不是等用户刷到再骂街。

**本项目用它的一条主线**：把散在各处「让生成式 AI 干判断活、再用字符串解析接住」
的地方，换成类型化判定；再在**花钱的生成调用之前**加一道便宜的价值预筛。下面
13 个候选全部围绕这条主线。

## 二、总设计纪律（每个落点都遵守，先立规矩）

1. **结构决定权永远在代码**：Jev 只回答「做不做 / 选哪个 / 几分」，永不碰
   冻结清单——srcKey 键格式与切块确定性、questionHash、wordKey、题块 kramdown、
   knKey、属性名，一处不动。Jev 的判定是概率性的、随模型版本漂移，**凡影响
   hash/结构的东西一律不给它决定权**。
2. **低置信回落现状**：每个落点写明 fallback = 现在的行为。没 key、超时、429、
   判定模糊（noul 落 0.2~0.8）→ 一律走现状路径，用户无感。
3. **判定结果 v1 一律不落盘**（现算现用）；唯一例外是同义词表——它本来就是
   纯派生可重建缓存，往里加条目符合既有口径。
4. **数据出境要知情**：题目内容、笔记原文会发到 typesafe.ai。设置里 jevKey 旁
   加一个总开关（默认开），说明文案写明「开启后转换/判分等场景会把相应文本发给
   TypeSafe」。不想出境就不填 key，一切 Jev 功能静默关闭。
5. **一次请求问完**：Jev 的原生能力是同一批 state 上并行问多个独立问题，所有
   落点都按「一片一问 / 一批一问」设计，不逐题发请求。

## 三、推荐落点（值得派单，6 个）

### A1. AI 转换质检（convert，出题之后、落库之前）

**现状**：解析成功即落库（`SetWriter`），烂题（答案不唯一、推不出、与材料无关、
题型转错）要等用户刷到才发现。

**加法**：每片题目解析成功后，把「片内全部题目 + 材料原文」打包问 Jev 一次：

| 问题     | 类型      | 判什么                               |
| -------- | --------- | ------------------------------------ |
| 答案唯一 | noul      | 没有「也对」的干扰项                 |
| 可推出   | noul      | 题干答案能否从材料推出               |
| 材料相关 | noul      | 题目和这段材料匹配（防 AI 凭空编题） |
| 题型正确 | noul      | 单选/多选/填空有没有转错形           |
| 质量分   | score 1~5 | 档位写死具体情形                     |

**政策**：任一 noul 落 0.2~0.8、或 score 置信 <0.7 → 不拦截，只在转换报告标
「Jev 存疑」+ 一句原因；明确踩雷（如可推出 <0.2）**同样只标不删**——静默丢数据
违反数据演进守则，删不删永远是人点。

**落点**：新文件 `src/ai/jev/convertChecks.ts`；`ConvertBatch.ts`（492 行贴红线）
只加一行调用；报告标注走现有报告组件加一列。

### A2. 切片预筛「值不值得出题」（convert，出题之前——你点题的那块）

**现状**：切块后唯一被跳过的是纯标题块（`isHeadingOnlyChunk`，
`SrcChunk.ts:209-211`）。引言、导读、章末小结、纯代码示例——全都会烧一次
**生成式出题 AI**，然后 AI 回一句「无可转内容」（计 `empty`，
`ConvertIncrement.ts:179`）或者 `CAN_CONVERT: no`。钱花了，题没有。

**加法**：整卷/增量的生成循环之前，把待转切片批量喂 Jev 一次问两个问题：
「这段包含可出题的知识内容吗？」（noul）+「出题价值打分」（score 1~5，1=目录/
导读/纯代码，5=定义+例题+结论密集）。判定「无可出题内容」（noul ≤0.2 且分低）
的切片**在进生成 AI 之前跳过**，报告里单独计一类「Jev 预筛跳过」。

**钱从哪省**：现在一片的 empty 结局 = 一次完整的生成调用（几千 token 进、几百
出）；预筛一次批量判定顶掉 N 次生成调用。文档里「没料」的切片占比越高省得越多。

**红线**：只决定「跳不跳」，切片本身、srcKey、hash 一概不动（纪律 1）；漏筛的
代价只是「少出几道题」且报告可见，误杀可控（阈值放保守，noul ≤0.2 才跳）。

**落点**：`src/ai/jev/chunkScreen.ts` 新文件；挂 `ConvertIncrement.ts:164-167` 与
`ConvertSegment.ts:124-126` 两处现有跳过点旁边。

### A3. 增量变更「值不值得重转」（convert，省费模式的智能档）

**现状**：`classifyChunks`（`SrcChunk.ts:153-204`）hash 两阶段分类出
相同/变更/新增/消失；省费模式对**全部变更块一刀切保留旧题**（`keepOldChoice`，
`IncrementDialog.ts:27-33`），非省费则全部重转。改个错别字和改道例题，待遇一样。

**加法**：变更块（新旧两段文本代码手里都有）逐块问 Jev：
「这次修改是否实质影响可出题内容？（新增知识点/改数值/改结论 = 是；措辞/排版/
错别字 = 否）」（noul）。省费模式下：实质变化 → 重转该块；措辞级 → 保留旧题。
非省费模式不变（用户要全量就全量）。

**红线**：同 A2，只决定「转不转」，指纹与键不动；判定不落盘，重跑重判无害
（最多多转一次）。低置信 → 当实质变化处理（宁可多转不漏转）。

### B1. 填空题语义判等（quiz 判分）

**现状**：填空判分是归一化后**精确字符串相等**（`normAnswerText`：
去空格/大小写/`$` 定界，`types.ts:266-268`；多答案靠 `a|b` 写法，
`QuestionGrading.ts:73-78`）。用户答「光合作用」标准答案「光合作用(photosynthesis)」
之外的任何同义表述——判错。填空不走 AI 判分通道（只有 brief 族走）。

**加法**：字面比对失败时，问 Jev 一次：「用户答案与标准答案（在题干语境下）
语义等价吗？数学等价形式也算」（noul）。≥0.9 → 判对，界面标「Jev 判同」；
≤0.2 → 维持判错；中间 → 维持判错但给个「拿不准」小标提示可人工改判。

**边界**：只在**字面失配**时触发（大多数作答是字面命中，零开销）；作答是交互
场景，Jev 判定模型亚秒级返回可接受；调用失败/没 key → 维持现状判错。判分主通道
永远是确定性代码，Jev 只做「判错后的复核」，这条写死。

**落点**：`QuestionGrading.ts` 的 `gradeSlot`/`gradeQuestion` 失配分支加一行
调用（组件内标记「Jev 判同」走现有作答态通道，不新增持久化字段）。

### B2. 同义词表判定换成 Jev（bank 知识点）

**现状**：`know-synonyms` 的 AI 捕获（`KnowSynJudge.ts`）把挂不上的知识点标签
批量送**生成式对话 AI**（`agentChatOnce` + 编号清单协议，prompt 在
`prompts/synonyms.ts`），再解析文本回写。这是「让作文型 AI 干判断活」的典型——
格式一歪整批作废。

**加法**：换成 Jev choice，逐对问「这两个知识点标签是同一概念吗？」
（same / related-but-different / different），批量并行；写回侧照旧
`putMany(writes, "ai")`（存储结构与缓存口径零变化）。解析代码直接删。

### B3. 背单词 AI 复盘换 Jev 判定（word）

**现状**：AI 复盘（`WordAi.ts:140-207` + `prompts/misc.ts:11-38` 的 W/L/C/T 行
协议）让生成式 AI 输出文本再解析，落盘 `applyAiReview`（`WordStore.ts:384-407`，
up 稳定度 ×1.4、down 减半）。

**加法**：生成侧换成 Jev：逐词问 choice「up / keep / down」+ noul「误认是手滑
还是没记住」。FSRS 公式与落盘动作一行不动（还是那三档按比例挪），**只换「选档」
这个口的供给方**。格式永不错；低置信的词维持原稳定度不动（比现在解析失败整批
放弃更细腻）。

## 四、可试落点（前三单跑顺、见过真判定质量后再拍，5 个）

- **C1. 易混词主动推荐**（word）：现在易混组只有三条来源——用户错答实证
  （`CardOps.ts:48-49`）、AI 复盘 C: 行（`WordAi.ts:104`）、预置表
  （`src/word/data/confusables.ts:3`，**空占位**）。没有主动推荐引擎。Jev 可在
  新学时对同书候选词对（代码先用编辑距离/同词根圈出）问 noul「这两个词容易混
  吗」，命中落 `addPair(...,"ai")`，存量结构零改动。
- **C2. remapKey 悬空重挂仲裁**（bank）：知识文档删除后 kp 引用悬空，现在只在
  同库标题**唯一**命中时自动重挂（`BankReconcile.ts:41-67`），多候选/近似候选
  全部留悬空。Jev choice 可在「唯一命中」扩为「Jev 高置信唯一命中」时补位；
  拿不准维持悬空现状。knKey 算法本身不动。
- **C3. 统计建议的证据挑选**（stats）：`buildStatsPrompt`（`misc.ts:41-68`）把
  全量成绩+错题清单塞给生成式 AI。Jev 先做 select-don't-generate：score 挑出
  「最值得进建议的 5 条事实」，prompt 变短、建议更聚焦。生成仍归生成 AI。
- **C4. 学伴台词变体选择**（companion）：规则层现在是「事件查表 + 台词表随机抽
  一条」（`CompanionCtl.ts:282-304`、`Lines.ts:43-100`）。Jev choice 可按连对数/
  答题节奏/时段在变体里**选最贴的一条**（仍是预写台词，不生成）——纯体验向，
  优先级最低。
- **C5. PR 预检升级：逐条声明核查**（调度基础设施）：现在的 jev-pr-review 是
  整体 7 问；标定已证明「逐条交付声明初筛」7/7。v2 可把 PR 描述里的「已验证/
  预期」清单拆条，逐条 noul + 人工对照表落评论。

## 五、明确不建议（想清楚了才敢说不行，4 个）

- **Jev 参与切点选择**（切片时决定从哪个空行切）：切点变了 → 块文本变 →
  srcHash 变 → **增量分类全乱、省费模式失效**——直接违反冻结清单「切块确定性」。
  Jev 的概率性本质和这项需求天然冲突，一票否决。
- **due 队列「今天优先学哪些」排序**：FSRS 的稳定度/到期已经编码了遗忘风险，
  再叠 Jev 打分增量存疑，还多一份出境内容。现有 `buildQueue` 书序够用。
- **客观题判分主通道**：选择/判断的精确匹配就是规格本身，Jev 只做 B1 的填空
  失配复核，不碰主判分。
- **knKey 聚合算法**：冻结清单点名项，聚合键裂开=薄弱画像分裂，不做任何
  「AI 参与归一」的尝试。

## 七、风险与对策

| 风险            | 对策                                                                      |
| --------------- | ------------------------------------------------------------------------- |
| Jev 判定不准    | 每个落点低置信/失败都回落现状；删题/改天数/改结构永远在人或确定性代码手里 |
| 误杀切片少出题  | A2 阈值保守（noul ≤0.2 才跳）+ 报告单列「Jev 预筛跳过」可人工复核         |
| 内容出境顾虑    | 总开关 + 设置页明示；不填 key 一切静默关闭                                |
| 服务不可用/限流 | 429/529 退避重试一次，再败走降级，不弹窗轰炸                              |
| 成本失控        | 批量问是默认形态；A2/A3 省下的生成调用远大于判定开销                      |
