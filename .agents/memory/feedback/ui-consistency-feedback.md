2026-08-25 用户直接贴侧栏工具栏 HTML 说「这个有点丑吧」。诊断出的丑点与修法（已落地 base.scss/CardHtml.ts）：

- 单图标套全宽 `b3-button--outline`（专题管理）像空盒子；小图标钮独占一行（统计）像漏渲染；工具区竖排 4 行浪费竖向空间 → 改两行：搜索一行 + 操作行（图标钮 + 主按钮 flex:1）。
- **搜索/文本输入必须挂 `b3-text-field` 类**——曾有 SCSS 注释声称"走思源 b3-text-field"但标记里根本没挂，渲染成浏览器裸样式。
- 图标钮统一幽灵风格（同头部刷新/设置钮），操作行用 `align-items:stretch` 让图标钮高度自动对齐 b3-button，跨主题不错位。

同日第二条（贴 DOM 问「是不是合并一下」）：**别留两层薄信息头**——`wengu-head`（只有计时器）+ `wengu-subhead`（文档名/轮次成绩）两行并成一行：信息 span 在左、计时器 `margin-left:auto` 靠右、`flex-wrap:wrap` 兜窄窗口；头部选择器绑定（`[data-timer]`、`data-act="side-toggle"`）保持原标记不受影响。

同日第三条（「AI转习题的配置太长了要支持滚动」）：**所有插件弹窗的 `b3-dialog__content` div 必挂共享类 `wengu-dialog`**（已覆盖 Convert/Collection/WeakDrill/Regen/Related 五个；SettingsDialog 是 config__panel height:100% 结构不需要）。根因是思源弹窗容器无 max-height（详见 [[siyuan-api-patterns]]），规则 `.wengu-dialog{max-height:calc(100vh - 200px)}` 让内容区自带 overflow 生效、action 按钮区常驻底部。

同日第五条（「怎么生成中还能更改表单…应该像做题一样打开预览但不能操作」）：**转换进行中的体验约定**——页签切到生成中文档的**只读做题预览**（`.wengu-previewing` CSS 藏作答位 + 不绑作答事件），不能只给进度条看不到内容；做轮中途开转换要先 `stopRound()` 收卷再接管页签（渐进预览曾被 `if (host.isStarted()) return;` 整条静默跳过，这就是用户「看不到内容」的主因）。（弹窗表单全禁用的原始要求已被 2026-08-26 转换流程页化取代：弹窗点开始即关、无需长禁用，见第九条；setBusy 禁用清单仍服务于 PDF 导入流程。）

同日第七条（「这个在哪勾选知识点啊」）：**让用户手填块 id 的输入行必须带显式选择入口**——知识点反链原本只有裸文本框（粘 id/siyuan:// 链接），用户预期是勾选、找不到入口即不可发现。已加「选择…」按钮弹文档勾选器（KnowPicker.ts：按标题/路径搜索 300ms 防抖、checkbox 多选、预勾选现值、确定回填 id 空格分隔；SQL 恒 LIMIT 100、关键词剥通配/引号防串坏）。顺带：ConvertDialog 曾涨到 506 行破 500 红线，表单标记已抽到 ConvertDialogHtml.ts——以后动转换弹窗标记去那个文件，加控件仍要同步 setBusy 禁用清单。

2026-08-26 第八条（转换弹窗连续三条指令定下「选择器优先」终态）：**手填文档 id 的地方一律给可搜索选择器 + 标题路径动态回显；一旦有了选择器，输入框和长提示就是冗余、要删**。演进：①「原位替换就不要生成位置」→ 生成位置/父文档两行在原位模式整体收起（控件值保留，PDF 导入落点仍可读），父文档必填校验只在另存模式生效；②「父文档可以动态联动吗」→ 单选选择器（KnowPicker 加 single 模式 radio + titleKey 自定义标题）+ 手粘/回填 id 防抖 300ms 回查 hPath 回显，找不到提示未找到；③「文档也改成选择吧，这个应该简单」+「有了选择就不要输入框的，也不需要多余的提示」→ 源文档同配；知识点行收成纯「选择…」按钮 + 已选文档标题路径回显（裸 id 不再示人）。联动逻辑抽 ConvertPick.ts（bindDocLink 单选联动 / echoKnowTitles 多选回显，回显查 getDocInfo 逐个串行 await——fetchSyncPost 并发会互相吞）；FormHtml.formRow 的 desc 改可选（空则不渲染说明行）。④源文档初版仍保留输入框（可手粘），用户再贴 DOM 点名「都选择了怎么还有输入框」→ 输入框连根删掉，id 藏隐藏 input 供转换/PDF 落点逻辑读——规则无例外，主字段也不留手粘入口；顺带陷阱：程序改 `input.value` 不触发 input 事件，PDF 导入 onImported 回填后须手动调回查函数刷新标题回显。

2026-09-15 第十九条（点名「移动端的设计稿没有使用思源的主题变量」）：**设计稿（design/\*.html 高保真原型）也必须走思源 b3 主题变量，不许自造硬编码色板**。定稿模式=自造令牌全部改写为 `var(--b3-*, 原亮色值)`——进思源跟随主题（含 Neo+ 深色），独立浏览器预览回退原亮色；语义淡色/按压态用 color-mix 从主题变量派生；SVG 图标色用 currentColor、var() 不能放 SVG 表现属性要写 style。移动端稿已按此修完入库（f1d8ffc），以后出设计稿直接按这个模式写，别再产第二份硬编码稿。

**Why:** 用户在意与思源原生观感的一致性，混用按钮风格/裸样式/随意对齐会被立刻点名；转换场景下「能实时看到生成内容但不可操作」是明确预期；作答字母与显示序号不一致也算不一致；id 是机器格式，让用户粘 id/看 id 都是错的方向——选得出、看得懂标题才是终态；长任务与用户失联（状态只在弹窗里、弹窗一关就摸瞎）也是错的方向；行内已有说明行时，回显再造一条平行信息行也算冗余；作答完成后的界面要直接是「结果物」（详情），不是带残骸的答题页；详情态主体信息必须紧贴头部，「美观的居中排版」会因顶部留白被点名——垂直空间宁可空在按钮上方。
**How to apply:** 新增工具栏/表单控件时：输入挂 `b3-text-field`，纯图标操作用幽灵钮，只让主操作带文字标签；`«` 收起按钮仍是文本字符，已提议换 svgIcon（如 iconLeft）未获答复，改动时顺手补上。以后再出现「填文档/块 id」类字段，默认按第八条做：选择器 + 回显 + 无关模式收起，不要再造裸 id 输入框；回显一律走 formRow 的 echoAct 槽（第十条），别在 config-items 插裸 div。词卡/大卡面排版默认贴顶流式下排，别自动加垂直居中。写新 hint/Desc 时按第十六条自检：一句说清「这是什么/何时生效/有什么后果」，括号里不许塞理由、架构词（通道/反链/归一/画像/枚举/协议）或迁移说明；UI 改版时同步检查该面板 hint 是否还在描述旧交互。相关：[[ui-rendering-strings-not-vue]]、[[pivot-to-ai-block-conversion]]、[[word-card-bubble-flip]]。
