用户的功能反馈常是无标点的密集碎片长句，多个症状与期望的方案混在一起。例（2026-08-26 转换超时反馈）：「生成会超过五分钟超时，继续转换不可用，已有转换在进行中，进度见页内转换条在 AI 生成弹窗中选择相同的文档，而是有个面板单独管理」——实为三件事：①批次超 5 分钟被总时长超时误杀；②超时后 ConvertRun 单例泄漏导致继续转换永久被拒、误报「转换中」；③要求弃用报错提示、改独立面板管理转换。

另有同音字笔误（疑似语音输入）：例 20260831「AI 绘画会话管理」实为「AI 会话管理」——按消息里列举的场景（判题/转换/标签）判读真实词，不追问。

**Why:** 用户不写结构化 bug 报告，逐词当单一问题处理会漏掉根因和真正的需求点（本例②才是主诉的「不可用」根因，③是方案指令）。

**How to apply:** 把这类消息当「症状清单 + 方向性需求」整句拆解，先做根因排查再一并实现闭环；不追问澄清（用户期望自主完成，见 [[work-rules-siyuan-plugin]]）。字符串级的误报文案（如「已有转换在进行中」）往往指向状态机泄漏而非真实状态。
