## 验证：agent chat 并发 + 指定模型（3.8.1 真机，机器 B）

背景：温故插件需要「并发 + 每场景指定模型」。旧认知（AGENTS.md）认为
agent chat 并发互斥、chatGPT 支持并发但不能指定模型，二者不可兼得。

结论（源码 + 真机双重验证）：

- `/api/ai/agent/chat` 的并发锁**按 sessionID 键控**（kernel/api/agent.go
  的 `runningSessions map[string]*runningSession`），非全局锁。
- 「并发互斥」假象根因：旧验证没传 sessionID → 全撞 `runningSessions[""]`。
- 每个请求可带 `model` 参数指定模型（值 = conf.json ai.providers[].models[].id）。
- 完整调用链（缺一不可）：
    1. sessionID 合法格式 `{14位时间戳}-{7位字母数字}`；
    2. `POST /api/ai/agent/saveSession` 落盘 `{id, revision, title, entries:[{id, type:"user", content}]}`，entries 至少一条 user 条目；
    3. `POST /api/ai/agent/chat` body `{sessionID, userEntryID, message, language, references, model?}`，userEntryID=user 条目 id（空串=最后一条 user 条目）；
    4. 结束清理 `POST /api/ai/agent/removeSession {id}`。
- 两轮并发测试均通过（双请求 event:done 零 busy）；假 model id 被拒
  「请先参考用户指南进行配置」证明 model 生效。
