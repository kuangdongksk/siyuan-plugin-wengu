## 转换加「分片并行」（破串行依赖链）

痛点：逐段自推进的批边界由 `@@TO` 决定 → 下一批窗口起点是本批产出，硬串行
（40 万字符 ≈ 67 批 × 22 秒 ≈ 25 分钟；带知识点时批内另有 1~2 次路由调用，实际更久）。
给过四种破链思路（重叠并行+指纹去重 / 章级分治 / 锚点预扫两阶段 / 投机预判），
用户选**章级分治 + 路由按片复用**。

核心洞察：**「任务并行单元」与「批边界」是两件事**——分片确定性、可并行；
批边界仍由片内 AI 的 `@@TO` 决定（「不切题」的性质完全保留）。

落地：

- 新增 `source/ShardPlan.ts`：`planShards(md, target, from)` **只在标题行取切点**
  （标题几乎总是题目的自然边界 → 绝不切在题中间），按剩余长度均分选最接近理想
  位置的切点；标题不足自动减片、**无标题文档退化为单片**（零风险退化）；`from`
  支持续跑（断点落在片中间也天然接续）。`CursorWindow.stepWindow` 加 `limit`
  参数（窗口不越片尾）。单测 9 + 1 例。
- 新增 `run/ConvertSegment.ts`：`runSegment(shard, deps)` 只跑片内自推进循环，
  产物经 `deps.submit` 交付，**不落库不报进度**（落库/进度归编排层）。
- `run/ConvertBatch.ts` 改编排：worker 池按 `parallel` 并发跑片；**片序闸门**
  （`submit` 前 `await gate[i-1]`）保证落库恒为**按源顺序的连续前缀**——SetWriter
  的题单顺序与材料链 `lastMaterialId`（小题引用文中紧邻其前的材料）顺序敏感，
  乱序会跨片错位；连续前缀也让**续跑断点仍是单游标**、终止「保留」语义不变。
  目标片数 = 并发度 × 2（消化片长不均）；任一片失败即中止其余片（finally 里
  放行全部闸门，防未启动片留下永不 resolve 的等待）。
- 并发度回归：弹窗「更多选项」+ 设置面板「默认转换并发」（1~4，1 = 改造前行为）。
  链路 `settings.convertParallel` → `quiz/index.ts convertParallelOf` → 弹窗
  `initialParallel` → `cfg.parallel` → `convertDocBatched`。

校验：tsc / svelte-check（0 err）/ eslint / prettier / vitest **532 例全绿** /
webpack 构建通过；产物装机 + md5 比对一致，插件已重载。

文档：AGENTS.md convert 域新增「分片并行」条目；incremental-hash-plan.md §四补
「分片并行对增量口径无影响」+ 两条「片级三态增量」后续路径（均未实现）。

## 分片切点分级（用户提「格式可能千奇百怪」后补做）

上一版分片只认 markdown 标题，旧版落文档产物（448k）退化为单片。用户确认要
覆盖并强调「用户给的格式可能千奇百怪」，故把**切点识别**做广、把**弱边界**踢出。

**关键事实（实测，先于设计确认）**：

- `ConvertBatch.ts:204` 在转换前已**剥掉含 `id="..."` 的 IAL 行**（正则 `^\s*(?:>\s*)?\{:[^}\n]*\bid="[^"]*"[^\n]*$`）→ `custom-plugin-wengu-*` 标记根本
  到不了分片层，不能当切点判据。剩下来的是 `{{{row` 超级块行（旧产物每题一个，
  实测 il3ufi4 剥后 222849 字符 / 197 个 superblock；o75d6xg 117104 / 68 个）。
- 全库拉 45 篇 4 万+ 文档原文统计：43 篇有 markdown 标题、2 篇零标题但超级块密。
- 抽查切点前后原文：`}}}`→`{{{row`、解析末尾→`#### 69.`，**都精确落在题边界**。

**设计（`source/ShardPlan.ts` 重写）**：

- 候选三级 `heading`（markdown `#`~~`######` + HTML `<h1>`~~`<h6>`）、`marker`
  （超级块 `{{{`、分割线 `---`、HTML 块级标签）、`qnum`（`第N题`/`习题N`/`(N)`/
  `N.`/`【…】`/`①-⑳`）。
- 选点改成**代价函数** `KIND_SCORE[kind] - 距离/span`（heading 1.5 / marker 1 /
  qnum 0.5）——质量优先，但距离差一个量级时让步。比原来的「分级 + 固定搜索半径」
  更稳（原方案在候选空洞处直接 break → kaygs2d 只切出 2 片）。
- **弱边界（空行、任意行首）不参与分片**：切点不在题边界上 → 片尾那道题被硬切，
  前片按「末尾没写完」跳过、后片只见后半截 → **漏题**，且硬切点与 AI 的 `@@TO`
  无关、事后无法校正。宁可退化单片。曾经设计过「重叠上下文 + `[END]`/`[START]`
  标记」，写完发现方向搞反（前片后读、后片不前视 → 两道残缺题），改对又必须靠
  AI 遵守约定；实测 0 篇文档需要它，遂**整体撤掉**（`markBodyEnd`/`BODY_END_MARK`
  已删干净）。
- `refineShards` **超长片二次细分**：贪心只是局部最优，某理想位置附近只有很远的
  heading、近处只有 qnum 时，质量优先会把切点推远留下超长片（iuthpkh 出现 19445
  vs 理想 9338 = 108%）。对 >1.35×理想片长的片在片内再补一刀。

**真机 45 篇实测（target=8）**：

| 指标             | 只用标题 + 无细分     | 分级 + 细分 |
| ---------------- | --------------------- | ----------- |
| 拿到 8+ 片       | 43/45（2 篇退化单片） | **45/45**   |
| 平均片长偏差     | 21%                   | **12%**     |
| 最大偏差         | 108%                  | **31%**     |
| 偏差 >50% 的篇数 | 5                     | **0**       |

`il3ufi4`（222849 字符）8 片 27390~28499（偏差 2%）、`o75d6xg` 8 片偏差 7%，
全走 marker 切点。极端情形（无换行、连空行都没有）仍退化单片——这类文档连
题目边界都无从判别，串行本就不是瓶颈。
