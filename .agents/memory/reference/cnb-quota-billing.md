20260916 查证 CNB 官方文档（docs.cnb.cool）+ 核对 AI Credits 实测账得出的计费口径，直接决定召唤 NPC 的省钱策略：

**CPU 核时两本账**

- **两种额度分池**：云原生构建＝CI 流水线（push/PR/crontab/手动触发，即 .cnb.yml 的 quality-gate），免费 160 核时/月（超额 0.125 元/核时）；云原生开发＝WebIDE/VS Code 远程工作区，**本账号 3200 核时/月**（官方定价页标准 1600，疑组织级加成）。核时＝核数×小时，每 5 分钟冻结一次（5min×节点规格），月底清零不叠加。两者底层机制相同（开发环境＝带 service.vscode 的流水线），只是计费池分开。
- **NPC 计开发额度不占构建额度**：官方 NPC 文档原文「NPC 视作开发场景，消耗云原生开发用量」——载体虽是构建流水线，扣的是开发池（与 .cnb.yml 头部注释一致）。召唤青简/复核随便召。
- **消耗构建额度的只有 quality-gate**（push+PR 双跑是 .cnb.yml 注释里的有意设计）：单次约 5~~8 分钟 ≈0.3~~0.5 核时（按 4 核估），实际月耗约一二十核时，无需节省。
- 备用：非营利组织可申请特权 6400/64000 核时/月。

**AI Credits 第三本账（扩 NPC 并行先触顶的是它，不是核时）**

- 只对 NPC/CodeBuddy/AI 评审计费：免费 500 credits/月，超出 0.05 元/credit，与核时互不侵占——**质量门流水线烧 CPU 不烧 credits，两本账别混算**（换算表里说的「构建次数」实为 NPC 召唤次数）。
- 实测（20260916 核账）：余额 **7166 credits = ¥358.30**；过去 170 次召唤平均 **10.81M tokens/次**；综合价 **PR 档 ¥0.119 / issue 档 ¥0.188 每百万 tokens**（issue 召唤＝全新开工上下文铺得大，贵 58%）；消耗速率 9/13–15 约 164 credits/天（峰值 235.7）、两周实烧 1010.57 ⇒ **续航 ≈176~~278 次召唤 = 30~~44 天**。
- **综合价 0.119~~0.188 落在官方 95% 缓存档区间（0.099~~0.198）⇒ 缓存命中实际已 ~95%**；「不吃缓存只剩 16~~32 次」是假想情形非现状。命中垮掉的信号＝综合价漂向 ¥1+/MTok，可用 get-build-ai-audit 逐流水线看单次 credits 趋势。旧结论「近零成本档」有误，实际综合价 0.1~~0.2 元/MTok。
- 分时价（DeepSeek V4.1-Flash 官方价卡）：高峰＝北京时间周一至周五 9:00–12:00、14:00–18:00，**其余时段（晚间/周末/午休）全部半价**；输入缓存命中 0.02~~0.04 vs 未命中 1~~2 元/MTok（20~~50 倍价差，命中率主导成本），输出 4~~8。

**缓存机制（20260916 用户追问「不同 NPC 吃不吃缓存」后核 DeepSeek 缓存文档）**

- **池按模型共享、会话间无隔离墙**：缓存对所有用户默认开启；归属范围官方未写死（CNB 若自有账号统一代理则可能全平台 NPC 共用一个池，方向有利、无法验证）。**换模型＝换池**：青简(deepseek)与复核(glm)互不相通，同为青简的多次召唤互相暖池。
- **命中＝完整匹配某个已落盘的「缓存前缀单元」**（受 SWA 影响已非朴素逐字节前缀）。跨请求公共前缀会被单独落盘：A+B 与 A+C 那对会话不命中，落盘公共前缀 A 后**第三轮 A+D 起才命中**——同模型不同任务的两个 NPC 会话从 issue 文本就分叉，跨会话只吃得到脚手架公共前缀（system prompt+工具定义+预置 AGENTS.md 段）。TTL＝最后使用后几小时到几天，尽力而为；只作用于输入，**输出永远全价计算**。
- **实测 ~90% 命中的真正来源＝会话内复读**：agent 循环几十次 LLM 调用，每轮把整段积累历史当前缀重读、全部按命中价计——10.81M tokens 大头是这个，跨会话共享只贡献脚手架一小截。
- 推论：①「小改重召」的真实代价＝新会话按 miss 价（1~2 元/MTok）重铺任务上下文＋重跑探索，**不是**命中率垮掉；②「攒批」省的也是上下文重建而非缓存，维持否决；③一天召几次的节奏刚好把脚手架焐在 TTL 内，无需刻意保温。

**省法排序（20260916 我的评估，用户未反对）**

1. 不急的整改/文档单挪闲时召唤（半价、零工作流改动，续航可拉到 2~3 个月）；
2. 退修收尾走 PR 线程（pull_request.comment@npc）不回 Issue 重召（issue 档贵 58%）；
3. 一轮退修把文件路径+验收标准+禁区给全，压缩 NPC 自探索与自复审轮次。

- **拒绝「攒批召唤」建议**——与一 Issue 一 NPC 一 PR 工作流冲突（AGENTS.md 20260913 并行口径），牺牲审查粒度不值得。
