# CNB 额度 · AI Credits · 缓存机制（20260916 核账定稿）

## 两本核时账，互不侵占

- **云原生构建**＝CI 流水线（push / PR / crontab / 手动触发），免费 **160 核时/月**；质量门这类流水线只吃这本账。单次质量门约 0.3~0.5 核时 → 160 核时够 300+ 次/月，无需省。
- **云原生开发**＝WebIDE 远程工作区 ＋ **NPC 召唤**；定价页标准 1600 核时/月（控制台显示 3200，应为组织加成）。NPC 载体虽是构建流水线，官方口径「视作开发场景，消耗云原生开发用量」——**NPC 随便召，不碰构建的 160 核时**。
- 核时＝核数×小时；每 5 分钟冻结一次（冻结量＝5min×节点规格）；免费额度月底清零不叠加。

## AI Credits（NPC 模型调用，与核时另算）

- 免费 500 credits/月，超出 0.05 元/credit（¥1＝20 credits）。
- **实测综合价（已含缓存命中）：PR 档 ¥0.119/MTok、issue 档 ¥0.188/MTok（贵 58%）**。该价落在官方 95% 缓存档区间；「不吃缓存」档要 1~2 元/MTok，差一个数量级——悲观换算是假想线，不是现状。
- 规模感（20260916 时点）：单次 NPC 召唤均值 10.81M tokens；¥358（7166 credits）≈ 19~~30 亿 tokens ≈ 176~~278 次召唤 ≈ 日常强度 30~44 天续航。

## 缓存机制（DeepSeek 上下文硬盘缓存，对所有用户自动开启）

- 池子按模型共享、跨会话无隔离；**换模型＝换池**（deepseek 与 glm 互不相通，同角色的多次召唤互相暖池）。
- 命中要求**完整匹配已落盘的缓存前缀单元**。不同任务会话从 issue 文本就分叉：跨会话只能命中脚手架公共前缀，且首轮分叉不命中，系统落盘公共前缀后第三轮起才命中；TTL 几小时~几天。
- 实测 ~~90% 命中率来自**会话内复读**：agent 几十轮调用每轮重读整段历史，历史全按命中价（0.02~~0.04 元/MTok）计；每条新内容只在第一次进上下文时按 miss 价（1~2 元/MTok）计一次。
- 输出永远全价，缓存只救输入。

## 省钱杠杆（性价比排序）

1. **挪闲时**：高峰仅北京时间周一~周五 9:00–12:00、14:00–18:00，其余（晚间/周末/午休）全半价——零改动续航翻倍，第一杠杆。
2. **退修收尾走 PR 线程**（pull_request.comment@npc），别回 Issue 重召（issue 档单次贵 58%）。
3. **一轮退修给全**：文件路径＋验收标准＋禁区，压缩 NPC 自行探索与自复审轮次。

- ❌ **不采纳「攒批再触发」**：牺牲 PR 审查粒度，且省的只是新会话重铺上下文的一次性 miss 开销，不值。
