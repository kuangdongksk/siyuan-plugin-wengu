2026-08-24 与用户讨论定稿的词书数据模型（**地基重构已动工**：2026-08-26 并行会话 98bcb1e/c19b9ef 把单词域迁 `src/word/` 完成分域；key 下标→词头改造与多词库管线仍待做）：

- **三层模型**：考试（考研/雅思/托福/四六级）= 词库域与进度隔离单位（saveData 按考试分文件如 words-kaoyan）；书 = 词库的**带序子集**（不只是顺序皮肤——核心词书⊂全量词书，收词范围也不同）；进度挂在 (考试, 归一化词头) 上，与书解耦。
- **现状问题**：words/mistakes/timing/notes/易混组所有 key 都是词书扁平下标，换书即错位作废。
- **换书行为**：核心→全量，已掌握跳过、差额自动进新学（符合先核心后全量的背法）；全量→核心，书外词状态保留不出队列、切回恢复；书内分级（高频/中频）=unit 分组，无新概念。
- **词头归一化口径**：小写、去词性标注、去括号注释；匹配不上的派生词条当独立词各背各的（多背几个词不错乱，比强行合并安全）；释义用当前书的。管线（tools 侧）负责清洗并生成归一化对照。
- **分两步实施**：① 地基重构——key 下标→词文本、cursor 整个删掉（新学队列=书序第一个无状态词）、存量 20 词无损迁移、WordImport 导入简化；② 多词库管线+考试/书切换 UI（纯增量）。建议与 word-timing 批次分开验证。

**Why:** 用户洞察「不同词书主要顺序不同、单词大差不差」+「有的只有核心词有的是全量」——这是不背单词的产品模型（书是皮肤、进度是资产），现状下标 key 撑不住换书/多书。

**How to apply:** 实施前先完成 [[wengu-word-timing-branch]] 待合并批次的验证合并；重构动 WordStore/WordView/WordConfusables/WordQuiz 全链 key 语义+一次数据迁移；易混组预置数据届时也应用词头而非下标。**2026-08-26 进展**：方向已成文 `docs/wordbook-redesign.md` §四（用户要求文档先行），第一版简化为**单层书列表+切换**（考试显式分层等有第二本书再上）、存储 `data/wengu/wordbooks/{id}.json`、头部书名做成选择器、起点面板加词书管理（导入 json/csv、删除不删进度）——待用户过文档 6 决策点，见 [[wengu-word-flow-redesign]]。
