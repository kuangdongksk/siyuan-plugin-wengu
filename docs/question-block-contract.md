温故插件把 AI 生成的题目存进插件题库（kramdown 契约格式），插件只：
从题库读题、页签内渲染/判分、写回状态、出统计。
本文件是「AI 把笔记块转换成题目块」时必须遵守的参数契约，
也是插件代码常量（`attrs.ts` / `types.ts`）的权威来源。

## 一、题目块结构（块优先，而非属性）

**一道题 = 一个超级块（Super Block）容器** + 若干带 `part` 标记的子块。

实际结构（已在真实思源验证）：

```
{{{col                                        ← 容器超级块，块上打属性
**题干……** 设 $...$ = ____                ← 子块 p   part="stem"
- A. $e$                                  ← 子块 l   part="option-0"
- B. $e^2$                                ← 子块 l   part="option-1"
> 正确答案：$e^2$                          ← 子块 b   part="answer"
> 解析文字……                               ← 子块 b   part="solution"
}}}
```

> 早期版本有 `part="mine"`（我的答案）子块——**已废弃**，作答在插件
> UI 里进行，不再写入文档；旧习题文档里的 mine 块会被插件忽略。

**转换完成标志**：容器块带 `custom-plugin-wengu-q = 1`。插件查询到
`attributes` 表 `name='custom-plugin-wengu-q' AND value='1'` 命中容器块 id
即认为转换完成，可以刷题。

## 二、容器块上要打的属性（前缀 `custom-plugin-wengu-`）

| 属性         | 必填         | 值                                                                                                                                                                                                                                          |
| ------------ | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `q`          | ✅           | `1`，转换完成标记                                                                                                                                                                                                                           |
| `type`       | ✅           | `single` / `multiple` / `judge` / `fill` / `brief` / `steps` / `cloze` / `match` / `essay` / `trans`（后四类与材料组见 §七）                                                                                                                |
| `steps`      | steps 题必填 | 按序竖线分隔的步骤类型：`method\|result\|result`                                                                                                                                                                                            |
| `group`      | 材料组题必填 | 所属材料块 id；AI 转换时写占位 `prev`（材料=文中紧邻其前的材料块），装载时插件按文档序解析回写真实 id（§七）                                                                                                                                |
| `src-key`    | 转换写入     | 生成该题的**源块稳定边界键**（结构切块：标题链 `H:章/节`、首标题前导段 `P0`、超长子块 `H:章/节#k`；20260903 起答案类子节「习题N/答案」并入父题块——一题一答口径，题干与解答同块进 AI），增量哈希二期（2026-08-31）起随转换写入题目与材料容器 |
| `src-hash`   | 转换写入     | 源块内容指纹（questionHash 同款双 djb2）；「重新导入」按它做三态增量分类（§重新导入）                                                                                                                                                       |
| `src-stale`  | 运行时       | `1`：源已更新但用户选择保留的旧题标记（增量重转换写）                                                                                                                                                                                       |
| `knowledge`  | 推荐         | 知识点/考点名                                                                                                                                                                                                                               |
| `chapter`    | 推荐         | 章节名                                                                                                                                                                                                                                      |
| `difficulty` | 推荐         | `1`~`5` 星                                                                                                                                                                                                                                  |

> `answer` 不再做属性存放——**答案就是容器内 `part="answer"` 的子块**。
> 判分原料是「我的答案子块」与「答案子块」的文本，不是属性字符串。

`type` 判分规则：

| type           | answer 子块写法         | 判分                                               |
| -------------- | ----------------------- | -------------------------------------------------- |
| single 单选    | 字母 `B` 或内容 `$e^2$` | 自动：比字母；或所选项内容与答案内容比对           |
| multiple 多选  | 字母串 `AD`             | 自动：子集不算对                                   |
| judge 判断     | `√`/`×`（或 `对`/`错`） | 自动                                               |
| fill 填空      | 用 `\|` 分隔可接受答案  | 自动：命中一个即对；带选项时输字母等价于输选项内容 |
| brief 大题     | 解析文字                | AI 判分并计入（可自评改判）；AI 不可用回落自评     |
| steps 多步引导 | 整题最终结果（可选）    | 自动逐步判分：见 §三点六                           |
| cloze 完形     | 可选（整题口径待定）    | E2 逐空自动（slot-k-answer，§七）；E0 自评降级     |
| match 新题型   | 槽位字母串 `D\|A\|G`    | E2 逐槽自动（§七）；E0 自评降级                    |
| essay 作文     | 省略                    | AI 判分（brief 同款三态；分档 rubric 是 E3，§七）  |
| trans 翻译     | 参考译文                | AI 判分（brief 同款三态，§七）                     |

> 比较对大小写、空白、`$` 数学定界不敏感 —— 真实转换（实测 2026-08-21）
> 的答案常写作 `$e^2$`，手输 `e^2` 应判相等。

## 子块 `part` 标记（打在容器下的各子块）

| part              | 含义                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| `stem`            | 题干段（可多段，按出现顺序拼接）                                                                         |
| `option-N`        | 选项子块，`N` 从 0 递增，对应字母 A、B、C…                                                               |
| `answer`          | 正确答案块                                                                                               |
| `solution`        | 解析/详解（闪卡卡背），可多个子块                                                                        |
| `step-k-stem`     | steps 题：第 k 步引导语（k 从 0，含方法标签）                                                            |
| `step-k-option-0` | steps 题：第 k 步选项块（一块多选项，按列表条目拆分）                                                    |
| `step-k-answer`   | steps 题：第 k 步答案——method 步写**全部可行方法**字母集合（如 `AB`，任选可行即对）；result 步写唯一字母 |
| `body`            | 材料块：材料正文段（可多段，按出现顺序拼接，§七）                                                        |
| `trans`           | 材料块：参考译文段（可选；组内题目全部判分后揭示）                                                       |
| `slot-k-option-0` | cloze 题：第 k 空选项块（k 从 0 即空号顺序，一块多选项按列表条目拆分，§七）                              |
| `slot-k-answer`   | cloze 题：第 k 空正确字母（E2 逐空判分；E0 判分前与 slot-* 一同 CSS 隐藏）                               |

> `mine`（我的答案块）已废弃：作答在插件 UI 进行，不再写入文档。

> `answer` 子块文本会先被插件清洗再判分：去引述 `>` 前缀、
> 去「正确答案：」类标签、`\|` 还原为 `|`（fill 多答案分隔）。
>
> 实测容错：一个 `option-N` 块里写多个选项（`- A. $e$\n- B. $e^2$`）
> 也支持 —— 插件按顶层列表条目拆分；非选择题带的选项会只读展示。

## 三、运行时状态属性（已停写——20260831 数据自托管起收进插件题库）

作答运行时统计（attempts / wrong-count / right / last-answer /
step-right / step-last / slot-right / slot-last / 文档级 total-time）
**不再写入块属性**，唯一真相是插件存储 saveData("bank") 的
`records[qid].stats` 与 `docStats[docId]`（细粒度编码与下表一致：
位图串 / 竖线序列）。停写前的存量值由装载后台链一次性回灌
（backfillV2 重扫：题库为零而块上有值时收编，顺带把块上残留属性
置空剥离）。下表保留为**存量兼容读**与编码契约：

| 属性          | 值         | 含义                                                         |
| ------------- | ---------- | ------------------------------------------------------------ |
| `attempts`    | 整数       | 刷题次数                                                     |
| `wrong-count` | 整数       | 累计答错次数（答错 +1 不清零）                               |
| `last-answer` | 文本       | 最近一次我的答案                                             |
| `right`       | `0`/`1`/空 | 最近一次正误                                                 |
| `step-right`  | `1010`     | steps 题：逐步最近正误（与 steps 属性对齐；AI 实时模式不写） |
| `step-last`   | `A\|B`     | steps 题：逐步最近作答（字母按步竖线分隔；AI 实时模式不写）  |

**文档块**（习题文档根块）上还写：

| 属性         | 值    | 含义                                                |
| ------------ | ----- | --------------------------------------------------- |
| `total-time` | 秒    | 累计刷题用时（已停写，自托管进 docStats）           |
| `source-doc` | 块 id | 转换配对：源讲义文档 id（转换时写入，契约属性照写） |

**镜像漂移检测（DriftWatch，20260831 自托管二期；20260903 随存储
pivot 整体退役）**：历史上题库 hash 是「入库时文档题块的内容指纹
基线」，ws-main update 广播触发三态比对（changed/fresh/gone）登记
`BankData.driftDocs`。题目内容唯一真相收进题库后无镜像可漂移，检测
与其提示行/采纳弹窗一并移除；`hash` 与 `RUNTIME_ATTR_HASH_RE` 剥除
名单保留（跨卷去重与增量重转换仍依赖指纹稳定）。

> **指纹剥除名单条款（20260901 数据演进守则）**：questionHash 归一化
> 里剥运行时属性的名单（`BankParse.RUNTIME_ATTR_HASH_RE`，当前八个）
> 与属性写入是**联动契约**——将来任何代码往题块/记录 kramdown 写新的
> 非内容属性（标记位、缓存值等），必须同步把该属性加进剥除名单，
> 否则写一次属性=变一次指纹，增量重转换全量误报「变更」。同理
> questionHash 的归一化规则与算法本体属冻结清单（见 AGENTS.md 数据
> 演进守则），禁原地修改。

**知识小节内容哈希（KnowHash，20260831 自托管三期）**：saveData
("know-hash") 按标题块 id 记知识小节的「包含式切段」内容指纹
（标题自身与其全部后代块直到下一同级/更高级标题）。导入根时写
基线；知识面板装载时比对出 stale 小节（一次性提示——基线自推进，
重开面板不重复报），小节行出「内容已变更」徽标；小节内容哈希同时
进路由缓存 RouteCache 的索引代数指纹（indexGenOf），小节正文变更
即整表作废路由缓存，宁漏勿错。（知识文档是用户自己的文档，不受
本 pivot 影响。）

**转换配对与孤儿清理（20260903 起退役）**：历史上习题文档根块的
`source-doc` 配对属性 + OrphanCleaner 实现「源删则题集连删」。题集
自持后源讲义删除**不再级联**（清理走「删除此题集」）；配对信息改存
`BankSet.srcId`。

**侧栏右键「删除此题集」/「重新导入」**（2026-08-29 起；20260903
随存储 pivot 改为纯题库操作）：

- **删除此题集＝清题库侧数据**：该集全部记录/材料/题集元数据/
  `doc:` 影子专题 + 会话历史一并清（removeDocData 口径），选中回退
  链自动切离。存量旧文档形态题集不动文档本体（插件已零读写，
  想删自己删）。
- **重新导入＝哈希检测优先的增量续做**（仅 `set.srcId` 源讲义
  仍存活时露出）：
    1. **增量重转换**（2026-08-31 二期起，题集记录带 src-hash 时
       优先——20260903 起压过续跑记录：指纹自愈已取代偏移断点，
       陈旧进度记录在此清掉，防「继续生成」重复生成已补块）：
       源文档重新**结构切块**（标题边界 + 指纹；答案类子节并入父题
       块——一题一答；纯标题块前置滤除
       ——零产物无指纹，留着会永远重算为「新增」），与题集记录已存
       `srcKey`/`srcHash`（20260903 起从容器 IAL 迁入记录字段，键
       格式/算法冻结不变）三态分类——**相同**（指纹一致，含边界
       漂移/标题改名）跳过零 AI 调用、原题与刷题统计原样保留；
       **新增**补生成追加到既有题集末尾（SetWriter 直写）；**变更/
       消失**逐块选：重生成（旧记录删除、统计作废）或保留（记录打
       `srcStale="1"`）/删除。**检测必过目**：先弹检测摘要（源共
       几块/已入库几块/本次待处理几块），逐块清单默认可调；设置
       「增量重转省费模式」=不出逐块清单只出摘要确认（变更/消失全
       保留只补新增）。全部相同直接收口「源未变化」。中止自愈：
       已入库记录自带指纹，重跑分类即「相同」跳过。终态点明
       **零产物块数**（AI 判定无可转内容的块不入库即无指纹，每次
       重导都会重算为新增，数量须让用户看到）。
    2. 指纹缺失（无 src-hash 的旧题集）且查得到该源的续跑进度记录
       （prefs convertProgress）→ **接着上次断点续写同一题集**（已
       生成部分是题库里的真实记录，无需读回），完全没有记录才清旧
       题集数据后从头重转（新题集），以上次转换设置（模型/填空转
       选择/大题拆步/知识点根；并发取设置默认），失败自动记回续跑
       进度延续上下文。无 `srcId` 配对的存量题集不露此项（报「无源
       讲义」）。

页签还会把**最近选中的习题文档 id、目录收起状态、上次计时方式**存到
插件数据（`Plugin.saveData("quiz")`，落 workspace `storage/petal/`），
重开时恢复。

## 三点五、数据存放分层（N 刷）

内核 SQLite **没有给插件建表的官方 API**（`/api/query/sql` 只读，直写
库文件有损坏风险），所以按归属分两层：

| 数据              | 存放                                        | 理由                           |
| ----------------- | ------------------------------------------- | ------------------------------ |
| 单题最新状态/累计 | 块属性（attempts/wrong-count/right…）       | 随文档走、SQL 可聚合           |
| 偏好/设置         | `saveData("quiz")` / `saveData("settings")` | 官方插件存储，小 JSON          |
| **N 刷会话历史**  | `saveData("history")`（HistoryStore）       | 按轮次维度，官方存储足够       |
| **薄弱画像**      | `saveData("weakness")`（WeaknessStore）     | 跨轮聚合的派生数据，2026-08-23 |

会话（`WenguSession`）：`{id, docId, startedAt, endedAt, mode,
plannedSec?, elapsedSec, stepsMode?, scope?, answered, correct, results[{qid, submitted, ok,
verdict?, comment?, cause?}], thoughts?{qid→思路文本}, clues?{qid→选段文本数组}}`
——开刷时创建、逐题作答时更新落盘、切文档/刷新/
关页签时收卷。`thoughts` 是收卷时对各题卡「思路」输入区的一次性快照
（未作答的题也保留）；总结报告的 AI 判卷 prompt 逐题带上思路，要求
点评方向/卡点/改进。文档头部据此显示「已刷 N 轮 · 最近 c/a · 最佳 c/a」。
`scope` 是复习模式的抽取范围（错题/未掌握等口径），`clues` 是线索
标注（M5）存的选段锚点（纯文本，不写块）。

### 薄弱画像（2026-08-23 起）

AI 判卷把薄弱处沉淀为跨轮次结构化档案（`weakness` 文件）：

- **聚合键**：题目解析里的知识点块引用（`kp:标题块id`，转换挂反链时
  注入，多个引用全计入）→ 无引用退化 `kn:knowledge词干` → `ch:chapter
属性`；一条都不会落（无锚点的题不进画像）。**kn 键走归一词干**
  （KnowledgeNorm，20260831 起）：「洛必达」与「洛必达法则」剥命名性
  后缀（法则/定理/定律/公式/原理/效应/现象/规则/准则/律）后同键——
  只动聚合键、不动存储数据（题卡角标仍显示 AI 原话）；宁漏并勿错并，
  动作/范畴后缀（计算/求法/性质…）不剥防误并。四处聚合点（knowledgeIndex

  weakness 存量旧 kn 键加载时折叠进词干键。**显示名取标准名**
  （pickStandardName=同簇信息最全的正式写法，如「洛必达法则」，不用
  词干短名）。
- **条目**：`{key, title, wrong(错+半对), total, lastWrongAt,
causes{错因键→次数}, aiNote(最近评语)}`。

  异步补记（causeApplied 名单幂等）——归因失败只丢错因不丢计数。
- **展示**：收卷报告「薄弱沉淀（累计）」区块 = Top 8（错数降序）。

## 三点六、多步引导题（steps）与 brief 的 AI 判分

**steps 题的作答语义**（一张卡内逐步解锁，不参与 after 统一揭示——
引导解锁依赖逐步反馈）：

- **每步独立计分**：每步一条会话记录，qid 为 `块id#步序`（如
  `20260822-abc#0`）；轮次统计按步计（answered/correct 每步 +1），
  文档侧聚合（SQL）按块计，两者口径不同是已知取舍。
- **整题口径**：right=全部步答对；`last-answer`/`step-last` 为各步
  字母按 `|` 拼接；题号导航一题一号。
- **method 步**（选方法）：answer 存**全部可行方法**的字母集合，
  任选可行方法即对——数学解法不唯一的结构性解法；**result 步**
  （中间结果）锚定参考路径，唯一解，干扰项来自常见计算错误。
  result 步给选项是**有意设计**：刷题时不动笔、只能心算，中间结果
  以四选一呈现把「算」变成「验证」；代价是离线模式锚定参考路径——
  选了非参考的可行方法后，后续中间结果仍按参考路径出（实时模式
  才真正跟随所选方法）。
- **方法步申诉（AI 复核）**：method 步答错时步结果行附「AI 复核」
  按钮——AiJudge 独立判断所选方法能否走通本题（`FEASIBLE: yes|no`
    - 理由），复核通过则该步翻对：会话结果原位改写（appealSessionResult）、
      块属性经 overrideStepsResult 翻 step-right/整题 right（不动 attempts，
      整题由错翻对时回退一次 wrong-count）、已收口的卡按收口快照+申诉
      集合重算整题结果。可行集合「标漏」的救济通道。
- **双模式**（开刷面板按轮选，记入会话 `stepsMode`）：
    - `offline`（默认）：作答转换时静态生成的步骤串；
    - `ai`：作答时 AiJudge 跟随学生所选方法逐步生成（串行队列），
      较慢且可能出错（选择处带警示）；失败可一键切回离线静态步骤
      重新作答（已产生的实时会话记录保留，会追加）。实时模式整题
      attempts/right 照写，但**不写 step-right/step-last**（步骤序列
      非静态、不可复现）。
- **渲染防剧透**：step-* 子块在卡片内嵌 Protyle 里被 CSS 永久隐藏
  （`[custom-plugin-wengu-part^="step-"]`），引导语/选项由插件按步
  Lute 渲染呈现，未解锁的步不出现。
- steps 属性缺失/非法时逐步按 result 容错；完全无步骤数据的 steps
  块按普通自评流程降级。

**brief 的 AI 判分并计入（三态）**：提交作答后走 AiJudge（同一智能体
端点，串行队列），「思路」折叠区若填了推导备注会一并送判——思路
输入正是判 partial 的素材。prompt 要求输出 `VERDICT: right|partial|
wrong` + `COMMENT:` 评语：

- **统计口径**：partial 记错（right=0、wrong-count+1，进错题重刷）；
- **展示口径**：partial 单列——结果行「◐ 部分正确——方向对但有缺口」
  （黄色），区别于全错；verdict 与评语随会话结果（`results[].verdict/
comment`）落库，恢复继续与统一揭示时仍按三态展示；战报每题条
  形图 partial 描黄、AI 分析逐题点名「部分正确」；
- **改判**：原自评按钮保留为改判入口（翻 right 并微调 wrong-count，
  不动 attempts；会话结果原位改写，verdict 随改判同步）；
- AI 失败/超时回落纯自评。

- 布局：左侧**可收起的文档目录**（习题文档按 hPath 分组，显示题量/

  AI 转习题弹窗填文档 id（支持 siyuan:// 链接）并可选 AI 模型
  （内置智能体端点）。
- **开刷面板四组选择**（进文档/刷新后先出现；行样式与插件设置同款：
  config-group 分组、标题说明在左、下拉在右）：
  ① 上次进度：继续上次 | 重新开始（有未完成轮才出现）——**继续=原样
  恢复**，选中后其余选项锁定并回显该轮原配置（含刷题范围），要换配置
  选重新开始；

  未掌握（历史错题且最近一次仍错，N>0 才出现）；后两者错题=新的一轮；

  倒计时归零提示时间到、仍可继续作答。刷新/切换文档/重开都视为上一轮
  结束、重新选择。
- **页签内可打开插件设置**：左侧目录头部「⚙ 设置」图标按钮
  （与刷新、收起并排；文字进 title 提示）。

- **计时**：页签每秒累计会话用时，头部实时显示总用时（文档块
  `total-time`），每 15 秒/作答/收卷/切换文档/页签销毁时落库——重开
  思源可继续刷，时间与进度都在。**页签不可见不计时**（2026-08-27 起）：
  温故页签被切走（`fn__none`）或窗口最小化时暂停每秒累计，
  「累计刷题用时」只反映真实面对题目的时间，不含挂后台的墙钟时间。
- **「结束本次做题」**（2026-08-25 起，大卷分次刷）：做题中头部出现
  「结束本次」按钮（已答 ≥1 才生效），点击＝提前收卷——总结报告/

  与错因按**结果水位**增量入账（`applied`/`causeApplied` 记
  `${会话id}#${结果条数}`，同一轮多次「结束本次」不重不漏；旧版纯
  id 条目视为全量已计）。下次进文档开刷面板「继续上次（已答 N）」

### 复习模式（错题本，2026-08-25 起）

- **入口**（头部切换器已删 2026-08-26，入口统一开刷面板三按钮
  「预览 | 开始刷题 | 错题回顾」）：「错题回顾」＝进复习模式；侧栏文档
  右键「错题复习」＝进复习模式并预筛该文档；统计面板总览「进错题本」
  按钮与文档详情错题行点击＝定位该题回看。复习模式退路：组头
  「重刷本文档」切回做题（通用「返回做题」入口挂账）。
- **数据源零新增持久化**：清单 = SQL 分页直查块属性
  `custom-plugin-wengu-wrong-count > 0`（显式 LIMIT/OFFSET，join blocks
  取文档归属与题干摘要；题块删除即自然从错题本消失）；「历次作答」
  时间线 = 打开错题本时扫 `history.sessions` 建内存索引（qid 归并，
  含 AI 评语/错因）；单题正文按 qid 惰性回源（getChildBlocks/hydrate，
  fetchSyncPost 串行天然合规）。
- **掌握口径（D4）**：未掌握 = 错过且块属性 `right="0"`（最近一次仍
  错）；已掌握 = 错过但最近一次对。「连续 2 次对才算」从严版挂账。
- **「刷」按文档进行**：清单按文档分组，组头「重刷本文档（N）」＝切
  回做题模式并以 scope=`wrongAll`（见开刷面板②）直落开轮；错题重刷
  轮照常入该文档轮次历史。会话落 `scope` 字段（`all`/`wrong`/
  `wrongAll`，旧记录缺省视为 all），「继续上次」按它恢复清单——
  错题重刷中断后不再展开为全量。
- **统计总览扩展**（D6）：错题概况（未掌握/已掌握 + 进错题本按钮，
  数据取错题本缓存，未打开过显示占位）、薄弱知识点 Top8（薄弱画像
  同步快照）、错因分布（画像 causes 按六键聚合的 CSS 条形）。

## 五、与平台机制对应（全部真实验证，思源 3.8.0）

- 自定义属性存 `attributes` 表 `name`/`value`，SQL 可查；单块属性
  `/api/attr/getBlockAttrs` `/api/attr/setBlockAttrs`。

* 容器块问：`/api/block/getChildBlocks`（`data[].id/type/markdown/content`）。
* 容器整块 kramdown：`/api/block/getBlockKramdown`（含全部子块源码+IAL）。
* 渲染：`window.Lute.Md2BlockDOM`。
* 闪卡 API（插件已不使用，留作内核备忘；3.x 起 API 改版，旧
  `/api/riff/addFlashcards` 等端点已不存在）：
    - 查/建/删卡组：`/api/riff/getRiffDecks`、`createRiffDeck`、`removeRiffDeck`；
    - 加/移卡片：`POST /api/transactions`（注意复数），
      `{reqId: 数字, transactions: [{doOperations: [{action: "addFlashcards" |
"removeFlashcards", deckID, blockIDs}], undoOperations: []}]}`；
    - `addFlashcards` 幂等（同块重复加不重复计）；
    - 注意：未知路由返回 200 + 空 body，不能用状态码判存在。

## 六、AI 转换（笔记文档 → 习题文档）

页签内「AI 转习题」按钮把所选文档交给思源自带 AI 转换（真机 3.8.0 验证）：

- **AI 通道**：`POST /api/ai/agent/chat`（SSE，独立 sessionID 并发+可按次
  指定模型，见 AGENTS.md；旧 `/api/ai/chatGPT` 直答 20260830 起弃用）。
- **输出协议（行协议，2026-09-02 起）**：prompt 强约束，格式外不许输出。
  先 `CAN_CONVERT: yes|no` + `REASON: 一句话`；可出题时每道题一个
  `@@Q … @@END` 块（QuestionDraft 行协议：@@Q 行带 type/knowledge/
  chapter/difficulty/steps/group/material 属性，@@P 部件标记
  stem/opt/ans/sol/body/trans/step/step-opt/step-ans/slot-opt/slot-ans，
  **选项只写内容不写字母**——字母由渲染按落盘顺序自动编 A、B、C…）。
  AI 判定不能出题（素材不足/无知识点）时插件展示原因，不生成文档。
  AI 不再手写 kramdown——`QuestionDraft.renderUnit` 把协议**确定性渲染**
  成 §一 的超级块形态落盘（格式正确性由代码保证；选行协议而非 JSON/
  YAML 的原因：数学 LaTeX 零转义、无缩进语义、漏 END 自动收口坏一题
  不坏一批，详见 src/convert/service/QuestionDraft.ts 文件头）。
  **纯标题块跳过**：结构切块里「标题行下无正文」的段（章标题直接挂
  子标题）不发 AI（isHeadingOnlyChunk），省白耗调用。

* **插图随题走**（2026-08-22 起 prompt 硬性规则；2026-08-23 补第 9 条
  +转换后自检；**20260903 起改占位符往返**）：源文档的图片行
  `![](assets/…)` 是某题依赖的插图（电路图/方框图/几何图）时，要求 AI
  把图片行**逐字复制**进对应题——题目依赖的图进**题干**（单独成段，
  part="stem"），答案/解析里给出的图（如解答画的方框图）进**解析**
  （part="solution"，防剧透）；不得改写路径/编造图片。**禁止因题里有图
  而整题跳过**（真机案例：AI 读不了图把「如图所示」的题弃掉——prompt
  第 9 条为此而设）。**占位符往返（20260903，MiniMax 2013 踩坑）**：
  内核 agent chat 会把消息里的 `![](assets/…)` 抠成图片附件、以
  `detail:"auto"` 发供应商——不认 auto 的供应商（MiniMax 只收
  low/default/high，报「invalid params, invalid image detail: auto
  (2013)」）整批必挂，且内核单请求最多 4 张图、多图静默丢——故
  `ai/PromptHygiene` 在发送口（client 两条公开通道）把图片行统一换成
  `〔插图:路径〕`占位（Lute 解析不出图片节点，内核零附件），prompt 规
  则改为「占位还原成图片行」；`QuestionDraft.cleanPartText` 兜底把模
  型漏还原的占位变回图片行——**落盘 kramdown 与旧产物逐字同构**，
  存量题集/指纹零影响。转换完成时插件比对源/产出的图片行数，有未带上
  的会在完成消息里警告（讲义配图不计漏）。注意 assets 路径是**笔记本
  相对**的——习题文档生成到其他笔记本（自定义父文档）时插图会失效。
* **落库（20260903 起，SetWriter 直写题库）**：批结果按「连续完成
  前缀」逐单元入 `BankRecord`——`renderUnit` 出契约 kramdown →
  `parseQuestionKramdown` 反解 + `questionHash` 指纹构造记录（与旧
  「落文档再回读入库」产物同构），材料进 `bank.materials`（小题
  group 写时直配材料 id），`set.qids`/`doc:` 影子专题随写维护，
  每批 `flush`（崩溃安全）。**原文档全程不动，文档树零新增**。
  （历史：20260823~0831 曾「原位替换/另存」双模式落文档，
  20260901 固定另存《源标题·习题》，20260903 随本 pivot 整体退役。）
  **父级定位必须用 hPath（`getHPathByID` 标题路径）**：内核按**标题**
  匹配 createDocWithMd 的路径段，用 .sy 文件路径拼段时，导入文档
  （文件名≠标题）会被自动重建一串以路径段为标题的空父文档（真机踩坑）。
  内核 Lute 解析 kramdown，两个实测硬约束：
    1. 超级块容器 IAL 必须**另起一行**紧跟 `}}}` 之后（写在同一行会
       解析出嵌套错误结构、属性丢失）；
    2. 块级公式用 `$$…$$` 各占一行；`\[…\]` 记法中的 `^` 会被解析成
       `<sup>` 导致指数丢失。
* **AI 高频偏差规整**（入库前，真机实测的三类偏差）：`q="2"、"3"…`

    自增序号 → 统一改回契约的 `q="1"`（SQL 按 `'1'` 检测）；子块 part
    属性漏右引号（`part="solution}`）→ 补全；题干「题干A：」前缀标签
    → 剥除（见 §四「题干标签清洗」）。

* **选择题选项洗牌**（2026-08-25 起，规整链尾部统一执行）：prompt 让
  模型「先写正确项、再补干扰项」，输出天然正确项居首 → 落盘答案
  恒为 A。规整后对 single/multiple 的 option-\* 与 steps 的每步
  step-k-option-\* 做 Fisher-Yates 洗牌并同步改写答案字母（judge/
  fill/cloze/match/essay/trans 无字母重排语义，原样保留；选项文本含
  「以上都对」「A 和 B」类位置敏感措辞时跳过该组，防指代错乱）。
  覆盖所有生成路径（转换 / 薄弱加练 / 知识点补题 / 题卡重生成——
  都过 extractBatchQuestions）。存量文档不追溯，重生成即洗。

- **可选转换开关**（弹窗内临时切换，默认值在插件设置页）：
    - 「填空转选择」：填空题改写为单选（原空答案作正确项 + 3 个干扰项）；
    - 「大题拆多步」：可分解的工科大题（每步有确定中间结果）改写为
      type="steps" 多步引导题——prompt 规则要求选定一条典型参考路径
      拆 2~5 步、方法分歧处设 method 步（answer 写全部可行方法字母）、
      其余 result 步考中间结果且干扰项来自常见计算错误；论述/证明/
      开放题仍生成 brief。
- **分批生成长文档（ConvertBatch）**：不再整篇截断到 6000 字符——
  源 kramdown 按 5000 字符（空行边界）切块，逐批调 AI 生成。
    - **渐进落库 + 渐进呈现**：每批按连续前缀写记录并 flush，页签用
      onBatch 携带的内存题目视图直接渐进呈现（无内核轮询；完成前
      屏蔽作答——题集可能被「丢弃」回收）。弹窗内另有渐进预览区
      （题号 + 题型徽标 + 题干片段，随批追加滚动）。
    - 前置检测调用（短超时）输出 CAN_CONVERT / COUNT / REASON；长文档
      不再只看前 12k 前缀（旧版 AI 只数可见部分、长卷必然报小——
      20260829 用户反馈「检测数远小于实际题数」）：按空行边界以 12k
      窗分段（复用 chunkKramdown 原语），各段走 agentChatOnce 独立
      会话**并行计数**（小池限流 4），prompt 按题干起点归属（段首
      残题不计、段尾未完照计），**各段之和=全文题数**；进度行实时
      显示「第 x/y 批 · 累计 c 题 · 上批 +k · 检测共 N（+）题」，N+
      只在有分段计数失败时出现（下限语义）；多批文档数不出时明示
      「长文档：总题数未确定，按批次计」。
    - 题量规则（prompt 规则 7）：原文是试卷/题库时**逐题全部**转换
      （不得限量/合并/漏题），讲义按知识点出题——这是「很多题只生成
      十道」的根因修复（旧规则写死「内容丰富时 5~10 道」+ 整篇截断）。
    - **并发生成（可选并发 1~4）**：agent/chat 并发会被内核拒绝
      （session is busy，真机 20260823 验证），并发批走旧直答端点
      /api/ai/chatGPT（无智能体会话、支持并发，模型跟随设置默认、
      不能按次指定——供应商 key 在 conf.json 中为密文，插件无法直连）。
      worker 池按并发数取批，结果按「连续完成前缀」拼装：题目顺序
      与渐进文档始终是原文档的忠实前缀；首个失败取消兄弟任务，
      终止/失败只保留已拼装前缀（断点偏移=前缀末尾，可继续生成）。
    - **终止生成**：页内转换条「停止」按钮 → AbortController 中断当前
      AI 调用，已累积部分二选一——保留进度（渐进文档已在，docId 记
      进度，可先刷）或全部丢弃（删渐进文档）。
    - **中途失败**：已渐进落盘的部分文档保留并记录进度（状态行提示）；
      首批前失败无渐进文档时，裸 kramdown 进进度记录。弹窗重开可
      「继续生成」。
    - **继续生成**：进度持久化在 prefs（源文档 id → {docId?/kramdown?,
      已覆盖源偏移, 批数, 题数}）；再次打开弹窗输入同一文档 id 时出现
      「继续生成」入口——上次保留内容（旧部分文档 kramdown 或记录里的
      kramdown）并入累积、从偏移处续跑剩余批；完成后删旧部分文档
      （如有）、按生成位置另存完整版。

* **从 PDF 导入（MinerU，2026-08-23 接入，2026-09-01 移除）**：转换弹窗
  曾可直接选 PDF 经 MinerU（用户 token，存 settings.mineruToken）解析
  建**原文档**再走转换；2026-09-01 随「原位替换」模式一并移除——转换
  固定另存、绝不动原文档后，PDF 中间产物文档会永久留在文档树，该管线
  失去意义。存量 MinerU 导入的文档照常作为源文档转换。
* 单批上限 6000 字符的实测背景：内核 AI 代理约 30 秒硬超时，实测 12k

    字符源超时空返回（`code 0` 但内容为空），6k 约 22 秒稳定返回 12 题。
    插件侧另有 5 分钟兜底超时，卡住时状态条报错而非永远「转换中」。

- **追加写入不可用（真机 3.8.0 验证）**：没有可靠的「向已有文档追加
  块」通道——`updateBlock` 对文档根传多块会把内容并成单段、对普通块
  传多块只保留第一段（**后续段丢失**）、`/api/transactions` 的 insert
  操作返回 code 0 但静默无效。因此一切增量都靠「累积后整体重建文档」。

* **知识点反链（KnowledgeLink，2026-08-23 起）**：转换弹窗可选填
  「知识点文档」（书架/书/章节文档 id，多个空格分隔，prefs 记住上次
  输入）。生效时每批生成前先做两级 AI 路由（输入只有批内容 + 标题
  索引，不导出正文——真机数据：61 章 304 万字、章中位 4.7 万字，
  正文挂载不可行）：
    1. 路由①：全部叶子章节标题清单 → 本批涉及的章（≤4）；
    2. 路由②：命中章的 h1~h6 标题清单（块 id 来自 SQL，清单字符预算
       2200）→ 相关小节（≤10），以 K 别名编入生成 prompt（规则 12：
       AI 在容器 IAL 追加临时属性 `custom-plugin-wengu-know="K1,K3"`，
       只能用清单内编号）。**小节 path=文档标题路径+祖先标题链**
       （20260831 起：headingsByRoot 取 subtype 建层级树
       buildSectionTree，path 沿树拼祖先链——此前是「文档路径/本标题」
       两段假层级，同文档不同 h1 下的同名小节会撞车）；
    3. 后处理（入库前）：别名映射回真实标题块 id → 在解析引述块尾追加
       一行 `> 相关知识点：((id "标题")) …`（并入 part="solution" 块，
       作答前随解析隐藏防剧透；无解析块时补独立 solution 块）→ 剥掉
       临时属性。**落盘题目格式与既有契约完全一致**，唯一新增是解析
       尾部的块引用文本。
       效果：知识点标题块的反链面板可见相关题目；题卡解析里点击引用跳转
       （Protyle 原生渲染）。路由任一步失败降级为「该批不加链接」，不阻断
       转换；完成消息里报告「N 题已挂知识点链接」。
* **知识面板层级树（2026-08-31 起）**：知识面板手动导入的知识文档
  （expandKnowDocs 递归展开登记根+全部后代）的小节从「平铺清单」升级为
  **h1~h6 层级树**——headingsByRoot 取 subtype，buildSectionTree 按
  「更低级挂前方最近更高级」的规则建树（跳级收编为子级，与大纲/文档树
  就近挂靠语义一致）；面板按文档树观感逐层折叠展示，题库推导的题数按

* **事后匹配（知识面板行「匹配」，2026-08-28 起）**：对**已入库的存量
  题**（不论新旧卷），逐题走同款两级路由，把命中小节以同一引用行格式
  **确定性注入**——先剥旧「相关知识点」行再注新（strip+inject=替换
  语义；默认跳过已有引用的题）。题库记录 kramdown 与 kpRefs 同步更新

  生成时即挂反链**。
* **文本关联 / 批量关联（KnowLinkText，2026-08-31 起）**：题库记录上的
  knowledge 标签与知识文档小节标题归一后（KnowledgeNorm 剥命名性后缀）
  **精确相等即确定性挂引用**——零 AI、瞬时；歧义（同键多小节）与过短
  （<2 字）宁漏勿错。两个入口：①**导入即关联**——知识面板「导入文档」

* **生成标签（侧栏文档右键，TagDialog，2026-08-31 起）**：对一份习题

  同款归一匹配挂引用，未匹配（标签在知识文档无对应小节）计数上报；
  ②**生成**（无标签的题，可关）：登记了知识文档时逐题两级 AI 路由，

  原位改值/末尾追加）+ applyTagToRecord（IAL+记录字段+引用+源块同步）。

## 七、英语材料组（E0-E4 已落地，2026-08-24；设计见 docs/english-question-review.md）

阅读/完形/新题型/翻译这类「一篇材料带多小题」的结构：**材料=一个
超级块**（带 `custom-plugin-wengu-material = 1`，**不带** q 标记，
不进题目列表、不计题数），内部子块 `part="body"`（正文，可多段）+
可选 `part="trans"`（参考译文）；**小题仍是普通题目块**，容器属性加
`group = 材料块id`。转换输出顺序必须是「材料在前、其小题紧随」。

```
{{{row
阅读文章正文……（完形的空位保留编号如 __1__）
{: custom-plugin-wengu-part="body"}

参考译文全文（原文档/解析有才写）
{: custom-plugin-wengu-part="trans"}
}}}
{: custom-plugin-wengu-material="1"}
```

- **group="prev" 占位与解析**：AI 写不出内核建块时分配的真实块 id，
  转换输出统一写 `group="prev"`（材料=文中紧邻其前的材料块）；页签
  装载时按文档序（blocks.sort）解析并 `setBlockAttrs` 回写真实 id，
  内存视图同步。渐进落盘期间不解析（文档每批重建，块 id 会变）。
  分批转换把材料与其题目切在不同批时，最终文档顺序仍保证解析正确
  （材料批先落盘）；prompt 明确「材料组题即使本批看不到材料也写
  group="prev"」。
- **英语四类 type 的运行时语义（E2/E3 已落地）**：
    - `cloze` 完形：语篇在材料块（空位编号在正文里），题块内每空一组
      `slot-{k}-option-0`（一块可含多个列表条目选项）+ `slot-{k}-answer`
      （该空正确字母），k 从 0 按空号顺序。**逐空作答**（SlotFlow）：
      空号条 + 当前空选项，提交本空即判（gradeSlot）；每空一条会话记录
      qid=`块id#空号`（同 steps 口径），全部作答完写整题账
      （attempts+1、right=**全空对**、`slot-right`/`slot-last` 逐空运行态，
      recordSlotsResult）。slots 不参与 after 统一揭示（逐空反馈依赖即时
      判分，同 steps 取舍）。
    - `match` 新题型：候选池写 `option-N` 块（7选5 的候选句/标题列表），
      answer 写槽位顺序对应的字母串（如 `D|A|G|E|B`）。渲染=候选池只读
        - 每槽一行下拉选字母提交，逐槽判分同 cloze（槽位数=answer 字母数，
          hydrate 聚合）。排序题（无候选池）仍走自评降级。
    - `essay` 作文：题干=题目要求（图片走插图随题走规则），answer 省略，
      solution=范文。作答=多行输入 + **实时词数**；判分走 AiJudge 的
      作文 rubric prompt（SCORE 分数档并入评语展示，如「8/20 — …」），
      三态/改判复用 brief 通道。
    - `trans` 翻译：题干=原句/原段，answer=参考译文，solution=采分点
      解析；逐句考查=每句一个题块、共用同一材料块（group 引用）。
      判分走采分点 prompt（同 brief 三态）。
- **材料组渲染（E1 分栏壳）**：DrillUnits 把列表组装成「独立题 /
  材料组」单元——组单元=上栏材料（独立滚动、可折叠、滚动位置按组
  记忆跨重渲染恢复）+ 下栏组内题**一次一题**（上一题/下一题导航、
  题号导航点击联动切题滚到组单元；组内全部题卡都在 DOM、非当前
  hidden，恢复/揭示/收卷等按 .wengu-card 遍历的既有流程全部保持；
  Protyle 惰性挂载=当前题+材料，切换显示后增量挂载）。
  **译文防剧透**：`trans` 子块 CSS 隐藏，组内题目**全部判分**后揭示
  （MaterialFlow.syncGroupReveal）；cloze 的 `slot-*` 子块随整题判分揭示。
- **线索标注（M5，会话数据）**：材料里选中一段 → 浮条「标为线索」→
  存进会话 `clues`（qid→选段数组，纯文本锚点不写块），组单元底部
  chips 展示；「AI 复核线索」走 judgeClue（CLUE: hit|near|miss + 点评，
  答错时错因二分定位错/理解错）。
- **生词标记（E4，联动背单词）**：材料/题干选中一个词 → 浮条「查
  生词」→ 词书检索（searchWords + 词形归一 lemmaForms：屈折后缀剥离
  回退）→ 弹释义卡 → 「加入生词本」写入共享 WordStore（words 状态
  置为今天到期进复习队列 + starred 星标），与背单词面板同一单例。
- **四模式开口（M6）**：QuizView.mode 枚举（quiz/review/study/preview），
  主区渲染按它路由——quiz=做题（默认）、review=错题复习（2026-08-25
  落地，见 docs/review-mode.md，侧栏右键进入）、preview=只读预览
  （2026-08-26 落地，PreviewFlow 装饰题卡：作答位摘除/正确项描绿/
  解析全展开，含「模糊答案」与快捷复制），study 仍预留（设计上复习
  模式的点句翻译/语法骑在材料组+文本锚定+按需 AI 上，到时不动分栏壳）。
