# 线索锚点与装饰渲染改造设计稿（v1，20260913 待审）

> 状态：**已过审（20260913 用户定夺）**。实施拆二期/三期，队列：#46（PR #50）→ #51 → 二期 → 三期，一次只跑一个 NPC。
> 关联：[#51 英语标线索不高亮](https://cnb.cool/sasa1107/open-source/si-yuan/siyuan-plugin-wengu/-/issues/51)（现行架构止血，照常走，本案把它定位为 fallback 地基）。

## 〇、一句话

线索锚点从「纯文本 + 渲染后文本匹配」改为「**权威原文坐标 + 渲染期按坐标施工**」；词表联动与线索 mark 收进**单一装饰出口**。思源行内标记的哲学（markup 唯一生产者、标记时刻一次求坐标）在「内容冻结 + 会话注解」约束下的等价移植。

## 一、病灶（为什么改）

1. **合成字符破坏匹配**（#51 根因）：词表联动往正文里注入原文没有的字符（上标「N·记号」），匹配 haystack 又把联动子树抠掉——选段与 haystack 永远对不上。任何未来「改写文本流的装饰」（音标、翻译、重点线）都会再踩一遍：**N 个装饰 × M 个文本消费方两两对 SKIP 口径**，是结构性病。
2. **装饰多 owner**：同一材料根，`applyGloss` 整段重铺一次、`ClueMarkDom.applyClueMarks` 再做一轮 DOM 手术，各带 SKIP 名单互相对口径、靠挂载顺序约定。
3. **文本锚点歧义**：同文重复出现只标首个（宁缺勿错），可能标错处；跨渲染只有文本这一种弱锚。

## 二、核心决策（逐条审）

### D1 权威原文坐标系 =「装饰注入前渲染产物的可见文本」 【定】

- 权威原文 := 基础渲染（`renderMdHtml(body)`）后、任何装饰施工前的**拼接可见文本**（文本节点序）。
- 坐标 := 该文本的字符偏移 `{start,end}`。
- **非权威区**（剔除出坐标系，不可锚定）：词表区（`ul.wengu-gloss`）、词表联动上标（`.wengu-gloss-sup`）、按钮/选项/解析区（沿用现行消费侧 SKIP 的施工名单）。选项区等本来就不出浮条，剔出只为防御。
- ⚠️ 已知风险点（实施时验证）：**公式区**（$桥 / mathRender 产物）文本形态复杂，先按非权威处理——跨公式选段走降级链（见 D6），数学卷现状能用的行为不回归。

**为什么不用 md 源串偏移**：md 语法字符（`**`、`^{}`、软换行）与可见文本非一一对应，选区在可见文本上，映射回源偏移需要逐字 source map——markdown-it 无现成机制，自己写 renderer 规则成本高且脆。可见文本坐标系下，「选区→坐标」就是文本节点内偏移累加，实现小一个量级；渲染确定性（markdown-it）+ 材料冻结（bank 契约）保证坐标跨渲染稳定。

### D2 锚点在「标记那一刻」一次求取（思源 setInlineMark 路数） 【定】

- 点浮条按钮（pointerdown）时 Range 还活着 → 从材料根的 CanonMap（挂载时产出，WeakMap<HTMLElement, Map> 持有）把 `range.startContainer/endContainer` 换算成权威坐标。
- 起止点落在非权威区（选在词表/上标上）→ 钳到最近权威边界；钳不出来 → 降级链（D6）。
- **chips 显示文本 = 权威文本切片**，不再用 `getSelection().toString()`——顺带消灭上标噪音（「evidence12·n.」→「evidence」），text 与坐标天然一致。
- 上标加 `user-select:none`（选区行为与口径一致）；iOS WKWebView 真机验证，不生效也不影响正确性（text 已走切片）。

### D3 存储：`clues` 不动，平行加 `clueRanges` 【定】

- `session.clues[qid]: string[]` 保留（显示/AI 复核/降级匹配源）。
- 新增 `session.clueRanges[qid]?: { s: number; e: number }[]`，**下标与 clues 严格对齐**；旧会话无此键 = undefined = 全走 fallback。
- 数据演进守则：optional、不 bump version、装载 backfill=undefined；删除线索两数组同下标同步。
- **渲染不回写坐标**（渲染是高频只读路径）；存量线索惰性升格——用户再次操作该题线索时才持久化坐标。

### D4 渲染期统一装饰出口（单模块单函数） 【定】

新模块（暂名 `quiz/service/MaterialDecorate.ts`），材料/题干挂载唯一入口：

```
decorate(root, { gloss: entries, clues: anchors[] }) → CanonMap
  ① root.innerHTML = renderMdHtml(body)                    // 基础渲染（现状同款）
  ② 收集权威文本节点表（非权威区剔除）→ 权威坐标映射        // CanonMap 主体
  ③ 词形联动施工：planGlossLinks 命中按权威坐标换算落格     // 现行 assignHitsToNodes 思路照搬
  ④ 轮间重算映射：③ 切过的节点表以权威坐标为中介重建映射    // 嵌套得以支持的关键
  ⑤ 线索 mark 施工：有坐标且校验通过→按坐标落格；否则文本匹配求坐标再落格
  ⑥ markSlots 施工序口径保留（节点升序+节点内起点降序）
```

- **嵌套显式定义**：线索 mark 在外层包住联动 `<u>`（mark=用户语义层，span=内容层），与 #51 语义一致。
- 消费侧 SKIP_SELECTOR 的「匹配用途」死亡（不再文本匹配）；「施工用途」瘦身为非正文区名单（③⑤ 都不进）。
- `GlossDom` 的词表区**渲染**（`@@G`→`ul.wengu-gloss`）保留，wrap 部分迁入（三期）。

### D5 渲染施工前坐标校验（防漂移自愈） 【定】

每次按坐标施工前校验：`权威文本[start,end] === 存储 text`。不等（材料被增量重转/数据错位）→ 该条降级文本匹配 → 再不行只出 chip。**坐标漂移从静默错误变成自愈降级**，宁可不出不亮错。

### D6 降级链（宁缺勿错保留） 【定】

1. 新锚点：CanonMap + 活 Range → 权威坐标（主路径）。
2. Range 已没（`lastSelText` 兜底路径）→ 文本匹配（#51 修复版）当次求坐标，求到即按坐标施工（本帧有效，不回写）。
3. 存量线索（无 clueRanges）：渲染时文本匹配（同 2，用完即弃）。
4. 全失败 → 只出 chip，不报错（现行语义）。

## 四、验收标准（实施 Issue 引用）

1. 新标线索：含词表词（连同上标）、跨段、跨 `**加粗**` 的选段高亮一次到位，mark 包住联动 `<u>`，上标不包 mark。
2. chips 文本 = 权威切片，无上标噪音；删除 chip 两击后 mark 同步消失。
3. 重开页签/组内切题回来/整壳重渲染：有坐标线索走坐标施工，稳定复现。
4. 存量线索（无坐标）高亮不回归（文本匹配 fallback）；增量重转把材料改了之后，错位线索被校验拦截，降级不亮错位置。
5. 数学/政治卷（无词表、含公式）行为零回归；公式区选段按风险点结论处理（不亮错、能亮照旧）。
6. 单测：Range→权威坐标换算、切片校验、轮间重算映射、嵌套顺序矩阵、降级链三分支、clueRanges 对齐维护（删/增）。
7. 四件套 + `pnpm build`；单文件 ≤500 行；数据演进守则全项核对。

## 六、明确不做

- 不把标记写进题库内容（材料/题干 md 是冻结契约，线索是会话注解）。
- 不引入 CSS Custom Highlight API（移动端 WKWebView 支持度未验；且不解决锚点问题，二期后如需可另议）。
- 不做渲染时坐标回写持久化（高频路径保持只读）。
