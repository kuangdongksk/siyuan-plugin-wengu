# 英语题型设计审核（讨论稿）

> 状态：**讨论稿，逐条过，不动代码**。分支 `wengu/english`。
> 背景：考研英语试卷题型如何落进温故现有契约
> （`docs/question-block-contract.md`，现题型 single/multiple/judge/fill/
> brief/steps，一题=一个自包含超级块）。本文先给分析，等用户逐条拍板。

## 一、总判断（讨论的起点）

1. **英语管线是「解析入库」，不是「AI 出题」**。题是现成的
   （真题/模拟卷），AI 的任务=抽取 + 重排成题目块 + 补解析，不是生成。
   现有 prompt 规则 7（试卷逐题全部转换）方向已对，需增加
   「识别材料组」的规则。
2. **契约的核心缺口是「一篇材料带多小题」**。阅读、完形、新题型、
   英一翻译全是这个结构；现契约一题一块自包含，直接套用=每小题把
   长文复制一份（一篇阅读的全文要复制 5 次）。
3. **判分骨架现成**：客观题（阅读/完形/新题型）走现有自动判分；
   翻译/作文 = brief + AiJudge 的英语专用判卷 prompt（翻译用三态
   verdict，作文用分数档）。AI 失败回落自评的通道也有。
4. **作答交互的壳已定：上下分栏**——上栏材料独立滚动、下栏题目
   不动（见 M3）。剩余的新交互只有完形点空、新题型配对、
   作文长文编辑+词数。

## 二、三个新机制（先定机制，再落题型）

### M1 材料组（一篇材料 + 多个小题共享）

- **方案 A（推荐）：平铺 + 引用**。材料=一个超级块
  （`custom-plugin-wengu-material = 1`），内部子块：
  `part="body"` 正文 + `part="trans"` **参考译文**（可选，真题解析
  的全文翻译，新需求 2026-08-23）；
  小题块仍是普通题目块，加属性 `group = 材料块id`。渲染时按 id 取
  材料 kramdown（getBlockKramdown，串行）。
  优点：题仍是一题一块，SQL 聚合/属性记账/孤儿清理/会话流程全兼容；
  材料只存一份。
  缺点：渲染端多一次按 id 拉块。
- **译文揭示时机**：对照译文本质是解析的一部分，推荐跟
  answer/solution 同规则（判分后/统一揭示后），防剧透机制直接复用；
  复习（精读）模式下是否给随时开关——待过。
- **方案 B：嵌套两级超级块**（组块包含小题块）。
  优点：结构直观，一次拉全。
  缺点：现契约全链路（SQL 查容器、getChildBlocks、attempts 记账）
  都假设题=叶子超级块；嵌套需要全链路改造。不推荐。
- **退化路径：材料复制进每题 stem**。最省事但阅读长文 ×5 份，
  转换 token、文档体积、渲染都浪费。仅作 MVP 兜底，不推荐。

### M2 一题多空（slots）

复用 steps 已趟通的语义，不改内核：

- qid = `块id#空号`（同 stepsQid）；
- 每空一条会话记录（steps 已有「每步一条、按步计 answered/correct」
  的先例与口径取舍）；
- 块属性 `slot-right` / `slot-last`（同 step-right/step-last）。

与 steps 的区别：steps 是**解锁式引导**（下一步依赖上一步反馈），
slots 是**并列空**（无依赖，任意顺序作答）。完形 20 空、新题型 5 槽
用它；英一翻译 5 句可用它、也可拆成 5 个独立 brief（见 §三.4）。

### M3 分栏滚动壳（材料组统一交互，方向已定）

- **布局**：主区上下两栏**独立滚动**——上栏=组材料（overflow-y
  auto），下栏=当前题作答区（不动/自身可滚）。做题时「滚上去看
  原文」，题目始终在视野里。
- **进入条件**：当前题带 group 材料 → 分栏模式；普通题维持现有
  卡片流。无材料时上栏隐藏（作文的「材料」就是题干本身：要求+
  图片放上栏）。
- **滚动位置记忆**：材料 scrollTop 按组记，组内切题不丢位置，
  切走再回恢复。
- **题号导航联动**：跨组跳题时上栏材料随之换（含滚动位置恢复）。
- **下栏粒度**（待过）：阅读=一次一题（组内上一题/下一题）；
  完形=当前空作答位+空号条；新题型=候选池+槽位作答位；
  翻译=句子+多行输入；作文=编辑器+词数。
- **渲染与风险**：材料用内嵌 Protyle 渲染（同屏只挂当前组一份，
  串行挂载规则天然满足）；Neo 主题改过 overflow（config__side
  横滚条旧坑），分栏 overflow 方案须在 Neo 下复验。

### M4 生词标记 → 背单词联动（新需求，2026-08-23）

刷英语材料时遇到不认识的词：**标记 → 查词 → 进生词队列 → 排期背**
（走背单词那套记忆排期）。

- **交互**：材料/题干文本里**选中**一个词（双击/拖选，只读 Protyle
  里用 window.getSelection 实现，不改块内容）→ 弹查词卡（复用
  wordbook 的词书查询）→ 「加入生词本」，**带原文例句**（选区
  所在句，词级笔记已有承接格式的话直接对齐）。
  （选中后的浮层操作菜单与 M5 线索标注共用。）
- **文中回显**：已标记词不写进块——材料挂载后按「本材料的生词表」
  在 DOM 上高亮（覆盖层），重挂载重新套。标记数据本身进 wordbook
  侧存储，不占块属性。
- **联动对接点（待定）**：走 WordImport 的导入格式，还是直接进
  WordStore 内部队列——取决于 word-timing 分支合流后的接口形态。
- **词形归一**：ran→run、showed→show。简单后缀规则先兜底，
  归一不了的批量交 AI（非实时）。原形+文中形都记。
- **待过**：标记入口（选中后浮按钮 vs 常驻按钮）；查词卡是页签内嵌
  还是跳 dock；背单词侧要不要回显「来自某篇阅读」的出处。

### M5 线索标注 + AI 判定（新需求，2026-08-23）

「选一段，标记它是第 N 题的线索」——**定位能力训练**：每道阅读题
在文中有其定位句/依据段，做题时把它标出来，AI 判断标得对不对。

- **交互**（与 M4 共用选中浮层：选中后浮出「标生词 | 标为线索」）：
  选段 → 关联题号（默认当前题，可改）→ 材料里按题号描色高亮
  （Q1 一色、Q2 一色…），下栏当前题下挂线索 chips（可删）。
- **存储**：线索=「题 qid + 选中文本（+所在段落序）」纯文本锚点，
  **不改块**。会话内进 `results[].clues`（同 thoughts 快照）；
  要不要持久到块属性（last-clues，错题回顾时看「当时标的定位」）
  ——待过。
- **AI 判定**：输入=材料全文+题干+选项+答案+（解析入库的定位句
  若有）+用户线索段，输出 `CLUE: hit|near|miss` + 理由
  （near=标到相关段落但不是定位句）。**诊断价值在答错时最大**：
  定位错 vs 标对但理解错是两类错因，判卷/战报里分开点名。
- **判定时机（待过）**：提交答案即判 / 仅答错时判（省调用、
  最需要）/ 手动「AI 复核线索」按钮（同 method 步申诉的交互范式）。
- **适用面**：阅读为主；完形（跨句呼应）、7选5（衔接线索）同机制
  可用，随对应题型期开放。
- **锚点鲁棒性**：材料只读不会被改，重渲染后按「选中文本+段落序」
  回位即可，模糊匹配风险低。

### M6 三模式框架（架构预留，2026-08-23）

远期三个模式：**做题**（现有一切）、**复习**、**学习**。模式是页签
主区的顶层组织维度，不是散落的功能开关。本分支只立开口、不实现
复习/学习。

- **开口做法**：
    1. 页签层引入模式分发：主区渲染按 `mode` 路由（先只有 quiz 一个
       实现），左侧目录/头部操作按模式适配；
    2. 会话已有 `mode` 字段——语义升级为模式枚举（quiz 先行），
       HistoryStore 结构不动；
    3. 学习模式（数学等学科的交互式 AI 学习）只占枚举位，不预设
       结构。
- **复习模式的英语场景**（点某句→看该句翻译→看该句语法）依赖的
  设施本分支全在建：M3 材料上栏 + 文本锚定（与 M4/M5 同源）+
  按需 AI（chatGPT 端点可并发）。到时新增的只是「句子级锚点 +
  逐句翻译/语法缓存」，不动分栏壳。逐句数据按需生成+缓存即可，
  不在转换时预生成（材料太长、翻译题外的句子未必看）。
- **分期落点**：开口在 **E1**——重写交互层时立架子最便宜，
  之后再加就是侵入式大改。

## 三、逐题型方案

### 1. 阅读理解 Part A

- **数据**：材料块（1）+ single 题块（5），题块带 group 引用。
- **作答**：走 M3 分栏——材料上栏，下栏一次一题（组内上一题/
  下一题，题号导航联动），一篇阅读连着做完。
- **判分**：single 现成，不动。
- **统计**：按题计（一篇=5 题）。
- **管线**：AI 需把「文章+5 题」识别为一个组、材料正文落 body 块；
  答案/解析（若卷子带解析）进 answer/solution。

### 2. 完形填空

- **数据**：材料块（正文含空位标记，`__1__` 或 ①…④）+ 一个
  type="cloze" 题块（slots=20），每空选项复用 steps 的子块模式：
  `slot-k-options`（一块多选项，splitOptionMd 已支持按列表条目拆分）
    - `slot-k-answer`。
- **作答**：M3 分栏——材料上栏（空位渲染成空号角标），下栏=当前空
  作答位 + 空号进度条；点材料里的空号角标即切到该空。
  （是否另要 20 行列表形态，待过。）
- **判分**：逐空自动（20 条记录，qid#k）；整题块 right 语义
  「全对才算对」太苛刻，倾向留空或 ≥17/20 视为过——待拍板。
- **统计**：按空计 20 条（与 steps 按步计同口径）。

### 3. 新题型（Part B）——工作量最大，全新交互

- **数据**：type="match" 题块：材料（含槽位标记）+ 候选池（7 项，
  option 块）+ answer=槽位→字母序列（`D|A|G|E|B`）。
  种类差异（通用机制的自然变体）：
    - 7选5：池=7 句，槽=文中 5 处；
    - 标题匹配/小标题：池=标题列表，槽=段落；
    - 多项对应（英二）：表格行=槽；
    - 排序：**无候选池**，answer=段序（如 `3|1|4|2` 对待排段）。
- **作答**：M3 分栏——材料（含槽位）上栏，下栏=候选池 + 各槽作答位
  （下拉/弹选）；排序题先不做拖拽，用「每个待排段选位置序号」的
  下拉（拖拽在页签内成本高，后补）。
- **判分**：每槽独立判（真题就是每题 2 分独立），answer 逐槽比对。
- **统计**：按槽计 5 条。
- **范围建议**：先做 7选5 + 标题匹配（最高频），排序、多项对应
  随后补——机制同构，只是槽的呈现不同。

### 4. 翻译

- **数据**：句组形态=材料块（划线句保留编号）+ **5 个独立 brief
  题块**（每句一题，group 引用材料）；整段形态=单 brief 题块。
  拆成 5 题（而不是 slots）的理由：逐句独立判分、独立统计/复习，
  闪卡语义好（一句一卡）。
- **作答**：M3 分栏——材料（当前句高亮）上栏，下栏=该句多行输入
  （现成 brief 作答位）。
- **判分**：AiJudge 翻译 prompt：输入=原句+参考译文+（解析文档若有）
  采分点，输出 VERDICT: right|partial|wrong + COMMENT（漏译/错译/
  语序/选词）。三态展示、partial 记错、改判通道全部复用 brief 现状。
- **注意**：判分串行队列已有；一句组 5 句=5 次串行调用，单句短，
  时延可接受。

### 5. 大小作文

- **数据**：type="essay" 题块（建议加类型值，理由见下）：题干=
  题目要求+图片（图画/图表作文的插图走已有「插图随题走」规则）；
  answer 留空；solution=范文。应用文/图画/图表用 knowledge 标注。
- **作答**：M3 分栏——题干（要求+图片）上栏，下栏=长文编辑器 +
  实时词数（词数区间从题干/属性来，如 160–200，不按卷种硬编码）；
  草稿随会话 thoughts 快照机制已有，需确认长文落盘时机
  （每 15s/作答触发，够用）。
- **判分**：AiJudge 作文 rubric prompt：内容切题/组织结构/语言
  准确性与多样性/词数，输出 `SCORE: n/满分` + 档次评语 + 修改建议。
  **会话结果需扩 score 字段**（verdict/comment 之外）；战报里作文按
  分数呈现而非对错。自评改判保留。
- 类型值问题：新增 `essay`（及翻译是否也加 `trans`）vs 全用 brief +
  属性路由。**倾向加类型值**：类型即文档、判卷 prompt/作答位/战报
  渲染都能按 type 直路由，且 TYPE_ALIASES 规整机制现成。

## 四、转换管线（前提已定：文档修复前置）

已定（2026-08-23）：MinerU 脏格式**不由转换器兜全责**。工作流=
「导入 → **AI 修文档**（用户迭代到满意）→ 再转题，**转换时还能
再规整一遍**」。转换器只保留轻量兜底规整（如选项内联拆分），
不为脏格式设计复杂逻辑。

- **挂账**：「AI 修文档」要不要做成插件内功能（导入后一键修复
  格式）——另行讨论，不阻塞本分支。
- **组不跨批**（转换器自身的正确性，与文档修复无关）：分批
  5000 字符的切点必须落在材料组边界（文章与其题目不拆开）。
- **答案分离**：题目/解析两份文档的合并同样可并入「修文档」环节
  （AI 把解析并进题目文档），或转换弹窗加第二文档 id 作备选——
  倾向前者，待确认。
- **图片**：插图随题走规则已有；assets 路径笔记本相对的坑已知。
- 其余（文件名≠标题、attributes 索引延迟、Lute 解析硬约束）
  已有对策。

## 五、工作量评估与分期建议

「几乎相当于重做」——一半对。分层看：

| 层                                           | 改动                                   | 量级       |
| -------------------------------------------- | -------------------------------------- | ---------- |
| 数据契约（types/attrs/契约文档）             | +材料组/slots/新类型值/译文子块        | 扩展       |
| 判分（QuestionGrading/AiJudge）              | 客观题不动；判卷新 prompt + score 字段 | 扩展       |
| 转换（ConvertService/ConvertBatch）          | 材料组识别 + 组不跨批 + 译文入库       | 扩展       |
| 会话/计时/统计/战报                          | slots 口径复用 steps；战报加分数呈现   | 扩展       |
| **页签交互（QuizView/CardHtml/AnswerFlow）** | 分栏壳 + 四类新作答位 + 生词标记       | **重写级** |
| wordbook 联动                                | 生词队列 + 例句 + 归一                 | 新增对接   |

页签层是重写级，但底下的数据/判分/转换/统计骨架都是扩展——
所以建议**分期、每期独立装机验证**，不做大爆炸合并：

- **E0 契约与转换**：M1/M2 数据形态 + 转换 prompt 识别材料组/译文
  ——英语卷能转成块。渲染先用退化视图：卡片流里「组头渲染材料块
