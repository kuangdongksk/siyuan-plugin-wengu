## 一、总判断（讨论的起点）

1. **英语管线是「解析入库」，不是「AI 出题」**。题是现成的
   （真题/模拟卷），AI 的任务=抽取 + 重排成题目块 + 补解析，不是生成。
   现有 prompt 规则 7（试卷逐题全部转换）方向已对，需增加
   「识别材料组」的规则。
2. **契约的核心缺口是「一篇材料带多小题」**。阅读、完形、新题型、
   英一翻译全是这个结构；现契约一题一块自包含，直接套用=每小题把
   长文复制一份（一篇阅读的全文要复制 5 次）。
3. **判分骨架现成**：客观题（阅读/完形/新题型）走现有自动判分；
   翻译/作文 = brief + AiJudge 的英语专用判卷 prompt（翻译用三态
   verdict，作文用分数档）。AI 失败回落自评的通道也有。
4. **作答交互是新活**：完形点空、新题型配对、作文长文编辑+词数，
   这三块 UI 现有作答位（chips/输入框）覆盖不了。

## 二、两个新机制（先定机制，再落题型）

### M1 材料组（一篇材料 + 多个小题共享）

* **方案 A（推荐）：平铺 + 引用**。材料=一个超级块
  （`custom-plugin-wengu-material = 1`，内含 part="body" 正文块）；
  小题块仍是普通题目块，加属性 `group = 材料块id`。渲染时按 id 取
  材料 kramdown（getBlockKramdown，串行）。
  优点：题仍是一题一块，SQL 聚合/属性记账/孤儿清理/会话流程全兼容；
  材料只存一份。
  缺点：渲染端多一次按 id 拉块。
* **方案 B：嵌套两级超级块**（组块包含小题块）。
  优点：结构直观，一次拉全。
  缺点：现契约全链路（SQL 查容器、getChildBlocks、attempts 记账）
  都假设题=叶子超级块；嵌套需要全链路改造。不推荐。
* **退化路径：材料复制进每题 stem**。最省事但阅读长文 ×5 份，
  转换 token、文档体积、渲染都浪费。仅作 MVP 兜底，不推荐。

### M2 一题多空（slots）

复用 steps 已趟通的语义，不改内核：

* qid = `块id#空号`（同 stepsQid）；
* 每空一条会话记录（steps 已有「每步一条、按步计 answered/correct」
  的先例与口径取舍）；
* 块属性 `slot-right` / `slot-last`（同 step-right/step-last）。

与 steps 的区别：steps 是**解锁式引导**（下一步依赖上一步反馈），
slots 是**并列空**（无依赖，任意顺序作答）。完形 20 空、新题型 5 槽
用它；英一翻译 5 句可用它、也可拆成 5 个独立 brief（见 §三.4）。

## 三、逐题型方案

### 1. 阅读理解 Part A

* **数据**：材料块（1）+ single 题块（5），题块带 group 引用。
* **作答**：两个形态——
  (a) 组视图：组内 5 题顺序作答，材料在组头渲染、**可折叠钉住**
  （滚动时 sticky），折叠状态记忆；
  (b) 逐卡：每张题卡内嵌折叠材料。
  推荐 (a)：一篇阅读本来就该连着做，材料一份 DOM 也轻。
* **判分**：single 现成，不动。
* **统计**：按题计（一篇=5 题）。
* **管线**：AI 需把「文章+5 题」识别为一个组、材料正文落 body 块；
  答案/解析（若卷子带解析）进 answer/solution。

### 2. 完形填空

* **数据**：材料块（正文含空位标记，`__1__` 或 ①…④）+ 一个
  type="cloze" 题块（slots=20），每空选项复用 steps 的子块模式：
  `slot-k-options`（一块多选项，splitOptionMd 已支持按列表条目拆分）
  + `slot-k-answer`。
* **作答**：两档——
  完整版：材料内空位渲染成可点角标（空号 chip），点击弹选项，
  下方 NumRail 式空号进度；
  简版：材料在上，下方 20 行作答位（空号 + A/B/C/D chips）。
  建议简版先行（纯 HTML/CSS，无弹层），点空交互后补。
* **判分**：逐空自动（20 条记录，qid#k）；整题块 right 语义
  「全对才算对」太苛刻，倾向留空或 ≥17/20 视为过——待拍板。
* **统计**：按空计 20 条（与 steps 按步计同口径）。

### 3. 新题型（Part B）——工作量最大，全新交互

* **数据**：type="match" 题块：材料（含槽位标记）+ 候选池（7 项，
  option 块）+ answer=槽位→字母序列（`D|A|G|E|B`）。
  种类差异：
  * 7选5：池=7 句，槽=文中 5 处；
  * 标题匹配/小标题：池=标题列表，槽=段落；
  * 多项对应（英二）：表格行=槽；
  * 排序：**无候选池**，answer=段序（如 `3|1|4|2` 对待排段）。
* **作答**：每槽一个下拉/弹选池项；排序题先不做拖拽，用「每个待排段
  选位置序号」的下拉（拖拽在页签内成本高，后补）。
* **判分**：每槽独立判（真题就是每题 2 分独立），answer 逐槽比对。
* **统计**：按槽计 5 条。
* **范围建议**：先做 7选5 + 标题匹配（最高频），排序、多项对应
  随后补——机制同构，只是槽的呈现不同。

### 4. 翻译

* **数据**：英一=材料块（划线句保留编号）+ **5 个独立 brief 题块**
  （每句一题，group 引用材料）；英二=单 brief 题块（整段）。
  拆成 5 题（而不是 slots）的理由：逐句独立判分、独立统计/复习，
  闪卡语义好（一句一卡）。
* **作答**：多行输入（现成 brief 作答位）；材料可折叠给上下文。
* **判分**：AiJudge 翻译 prompt：输入=原句+参考译文+（解析文档若有）
  采分点，输出 VERDICT: right|partial|wrong + COMMENT（漏译/错译/
  语序/选词）。三态展示、partial 记错、改判通道全部复用 brief 现状。
* **注意**：判分串行队列已有；一篇 5 句=5 次串行调用，单句短，
  时延可接受。

### 5. 大小作文

* **数据**：type="essay" 题块（建议加类型值，理由见下）：题干=题目
  要求+图片（图画/图表作文的插图走已有「插图随题走」规则）；answer
  留空；solution=范文。小作文/大作文用 knowledge 标注（书信/通知/
  图画/图表）。
* **作答**：长文多行输入 + 实时词数（英一 160–200、英二 ≥150 的
  区间提示）；草稿随会话 thoughts 快照机制已有，需确认长文落盘时机
  （每 15s/作答触发，够用）。
* **判分**：AiJudge 作文 rubric prompt：内容切题/组织结构/语言
  准确性与多样性/词数，输出 `SCORE: n/满分` + 档次评语 + 修改建议。
  **会话结果需扩 score 字段**（verdict/comment 之外）；战报里作文按
  分数呈现而非对错。自评改判保留。
* 类型值问题：新增 `essay`（及翻译是否也加 `trans`）vs 全用 brief +
  属性路由。**倾向加类型值**：类型即文档、判卷 prompt/作答位/战报
  渲染都能按 type 直路由，且 TYPE_ALIASES 规整机制现成。

## 四、转换管线风险（MinerU 卷子的已知特征）

* **选项挤一行**：MinerU 导出常见「A. xx B. xx C. xx D. xx」同段；
  现 splitOptionMd 只按列表条目拆，需加内联拆分
  （按 `(?=[A-D][.、])` 切）。
* **组不跨批**：分批 5000 字符的切点必须落在材料组边界
  （文章与其题目不拆开）。
* **图片**：图画作文插图随题走规则已有；assets 路径笔记本相对的
  坑已知。
* **答案分离**：真题卷常是「题目文档 + 答案解析文档」两份——
  转换时能否合并入题（两个文档 id 一起喂）？待讨论。
* 其余（文件名≠标题、attributes 索引延迟、Lute 解析硬约束）
  已有对策。
